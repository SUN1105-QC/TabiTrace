# 推荐探索 V2：设计包落地与验收

## 范围与依据

2026-10-31，依据用户提供的 `D:\download\Tabi_Explore_Redesign_Kit`：开发指令、参考效果图、asset-map 和 10 张 WebP。
技术栈沿用 Next.js 16 / React 19 / CSS Modules / Lucide、Spring Boot 4 / MyBatis / Flyway / MySQL 8。
入口 `/explore`，真实开放的城市页 `/explore/tokyo`。沿用现有导航、账户、收藏与地点加入旅行权限。

## 审计与数据来源

修改前只有 `official_cities.TOKYO` 为 ACTIVE；大阪、京都、首尔、台北来自前端固定目录。
原城市 API 仅允许 ACTIVE，不能把预告城市当作已经开放的指南。
现有 destinations 是创建旅行使用的参考目录，不能把其中所有目的地当作已发布指南。
台北的原始目的地代码 TW 保留；展示目录继续沿用此前中国主题下的中国台湾分组，未改动目的地参考归属。

新增只读公开接口 `GET /api/v1/official-cities/directory`，不要求登录；查询仅含明确发布的国家、目录条目和允许公开的城市状态。
不返回用户、旅行、照片、付款、草稿或管理可见性字段。国家和城市来自数据库；前端仅按国家/城市代码映射美术素材。
两次批量查询取得主题及城市，地点/路线数量由公开官方内容聚合，不逐城市请求。
统计只把 ACTIVE 且有已实现入口的城市计为已开放；预告不开放原有详情 API，也不提供虚假链接。

## 兼容迁移、备份与回退

V23 只新增 explore_countries、explore_city_entries 及此前已展示的四个预告城市元数据。
不修改既有 ACTIVE 城市、账户、旅行、照片、支付或其权限。已有同代码城市不会覆盖状态，DRAFT 不会自动发布。
现有接口仍按 ACTIVE 读取，原来的旅行与城市功能不依赖新增表。
迁移前已做本地一致性备份：`backend/.tabitrace/before-explore-v23-2026-10-31T02-23-55-306Z.sql`，183738 字节；不进入版本库或 public。
回退界面可恢复此前前端实现，保留兼容的新表和接口；无需删除目录表或回滚业务数据。全量应用回退包应保留已应用 V23 迁移文件以维持 Flyway 校验。
备份仅作为灾难恢复手段，不能直接覆盖迁移后新增的用户数据；本次不执行任何删库、清库或反向数据迁移。

## 界面与素材

采用暖色杂志式主视觉、带缩略图的国家选择器、国家插画横幅、三列城市卡片；桌面内容最大宽 1320px。
手机单列、平板双列，保留搜索、国家/开放状态组合筛选、地址恢复与清除筛选。
国家数量动态生成；新国家使用通用主题，不需要新增硬编码业务列表。
只有一座城市时仍保持合理卡片宽度；每国家初始最多三张，点击再加载六张，避免大量城市同时请求封面。
优先真实城市封面，其次对应设计包插画，最后中性占位。图片失败有连续回退；占位不会循环请求坏图。
设计包图片明确标记 AI 风格示意，保留素材映射及来源说明。未使用不存在的故事数或示例计数。
加载不显示假统计，失败可重试，无目录/空国家/筛选无结果均有可理解的状态。
二级按钮进入现有 `/trips`；所有预告卡片均无入口链接。
