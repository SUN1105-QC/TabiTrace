# 全量数据库迁移验收

`MySqlSchemaMigrationIntegrationTest` 使用真实 Flyway 将全新 MySQL 空库从 V1 迁移至 V23；它不启动 API、不发邮件、不读写对象存储，也不操作任何现有业务库。

## 安全边界

- 默认跳过，只有显式提供 `SCHEMA_TEST_DB_URL` 才会执行；用户名与密码必须分别提供为 `SCHEMA_TEST_DB_USER`、`SCHEMA_TEST_DB_PASSWORD`，不复用生产默认凭据。
- 仅接受 localhost / 127.0.0.1 / ::1，库名必须以 `_schema_test` 结尾。生产常用的 `tabitrace` 和支付测试过去使用的 `tabitrace_test` 均会被拒绝。
- JDBC URL 只允许基本连接参数；拒绝嵌入凭据、自动创建数据库、初始化 SQL 等可能在安全检查之前产生写入的选项。
- 连接后再次确认实际数据库名称，并要求没有任何表。发现既有对象立即失败；不会自动清空，不调用 Flyway `clean`，不执行 `DROP`。
- 完成后保留该专用库供排查，不能在同一个已迁移库上再次作为“空库”运行；应由操作者提供另一个新建专用空库。CI 的一次性 MySQL 服务会随任务结束销毁。

## CI

后端 CI 服务创建 `tabitrace_schema_test`。全量迁移用独立的 `SCHEMA_TEST_DB_*` 变量启用；支付、成本、删除等随机前缀专项继续用 `PAYMENT_TEST_DB_*` 指向同一专用测试库，各专项只管理自身随机前缀表。

全量迁移检查包括：V1–V24 全部成功（V24 另断言三座新城市各 30 个地点、6 条完整路线、目的地关联与目录排序）、校验和验证、二次 migrate 无重复执行、完整表清单、没有演示账号与旅行等业务数据、官方产品目录种子、全站渲染锁、财务记录保留外键与成片清理任务独立生命周期、关键新增字段及旧字段移除。

## 本地运行

先由操作者建立一个空的专用 schema，并给测试账号授权该 schema。只在当前进程里设置上述三个变量，然后执行：

```powershell
mvn -B -ntp -f backend/pom.xml -pl api "-Dtest=SchemaTestDatabaseGuardTest,MySqlSchemaMigrationIntegrationTest" test
```

没有提供专用空库时，只运行安全保护单测：

```powershell
mvn -B -ntp -f backend/pom.xml -pl api "-Dtest=SchemaTestDatabaseGuardTest" test
```

安全保护单测通过或测试编译成功，不等于真实 MySQL 全量迁移已经实测通过。该专项也不替代现有业务库与空库的结构对比，或真实注册、上传和视频端到端验收。
