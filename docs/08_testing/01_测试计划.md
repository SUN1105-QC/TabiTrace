# 测试计划

本文说明有哪些测试、怎么跑、覆盖什么、缺什么。产品层面的验收标准见 [MVP 验收标准](../01_requirements/02_验收标准.md)，当前阶段的验收标准见 [开发执行计划](../10_development/03_开发执行计划.md)。

## 1. 测试层次

| 层次 | 工具 | 位置 | 数量（2026-10-13 实测） |
|---|---|---|---|
| 前端单元测试 | Vitest 3（Node 环境，只测纯逻辑与会话刷新，不做组件快照） | `frontend/tests/unit/` | 5 个文件，55 个用例，全部通过 |
| 后端单元测试 | JUnit 5 + Mockito（含 spring-security-test） | `backend/api/src/test`、`backend/video-worker/src/test` | api 35 个测试类 165 个用例、worker 4 个类 7 个用例，全部通过 |
| E2E | 自研 Node 脚本，用 Chrome / Edge DevTools Protocol 驱动真实浏览器（不用 Playwright） | `e2e/` | 默认 6 个套件 119 项，全部通过 |
| 集成（外部服务） | 同上 | `e2e/integration/` | storage（默认运行）、email（需要模拟 Resend，默认不运行） |
| 静态检查 | `tsc --noEmit`、ESLint 9 | `frontend/` | 0 error，108 warning |
| 连库集成测试 | **没有** | — | H2 在依赖里但未使用；没有 `@SpringBootTest` |
| 性能 / 安全扫描 | **没有** | — | — |

## 2. 命令

```bash
cd frontend && npm run typecheck && npm run lint && npm run test     # 前端检查
cd frontend && APP_URL=https://tabitrace.example npm run build        # 生产构建（必须给 https 的 APP_URL）
cd frontend && npm run check                                         # typecheck + lint + test + build
mvn -B -f backend/pom.xml test                                       # 后端测试
cd frontend && npm run test:e2e                                      # E2E 默认套件（需要整套服务在运行）
node e2e/run.mjs auth-session                                        # 只跑某个套件
node backend/scripts/verify-empty-db.mjs                             # 空库迁移验证（需要空库与权限）
```

⚠ `npm run build` 和正在运行的 `next dev` 共用 `.next`，构建后要重启开发服务器。

## 3. E2E 套件

| 套件 | 覆盖 | 前提 |
|---|---|---|
| `critical-path` | 注册（邮箱验证码）→ 登录 → 创建旅行 → 快速打卡（含照片）→ 照片墙上传 → 修改设置 → 退出；校验服务端数据与会话吊销 | 开发邮件接收器在运行 |
| `auth-session` | 令牌只在内存、refresh 只在 HttpOnly Cookie；刷新页面、多标签并发刷新、令牌过期重试、会话吊销、无限刷新防护、未登录拦截、跨标签退出、CSRF | 测试账号 `E2E_EMAIL` / `E2E_PASSWORD` |
| `mobile-layout` | 14 个页面在 360 / 390 / 430 / 768 / 1440 宽无横向溢出、底部不被导航遮挡；快速打卡弹层不超出屏幕 | 测试账号且至少有一段旅行 |
| `images` | 头像小图、照片墙三档 srcset、隐藏的 Hero 不下载、推荐探索各屏幕像素够用、首页截图档位 | 邮件接收器（自带注册） |
| `trip-pro` | 升级页四种状态（未登录 / 免费 / 模拟支付升级 / 终身 Pro）的按钮与文案、成果入口、锚点、底部购买条 | 邮件接收器 |
| `storage` | 预签名、真实 JPG / PNG 上传与访问、元数据、20MB 上限（正好 / 超出 / 接近）、删除后 404 | 测试账号；FREE 账号要用 `E2E_TRIP_ID` 复用已有旅行 |
| `email`（不默认） | Resend 请求契约与失败处理 | API 以模拟 Resend 模式启动 |

测试账号的准备与清理：见 `e2e/README.md`。清理时**按本次新建的 id 删除**，不要按邮箱前缀批量删除（曾经误删过其他测试账号）。

## 4. 单元测试覆盖的重点

认证与会话（注册、登录、重置、退出、刷新 Cookie、JWT、客户端 IP）、邮箱验证、生产配置校验、旅行创建与官方探索、打卡日期、快速打卡、最近记录、成就计算、照片分页、本地 / R2 存储、分享隐私（坐标粗化）、方案配置与支付可用性、会员、我的音乐（含音频探测）、分镜、音乐片段、曲库、回忆、目的地搜索、天气；Worker：画面比例、文字换行、生产配置、音乐读取。

## 5. 重要业务用例（回归时优先检查）

| 类别 | 用例 | 自动化 |
|---|---|---|
| 正常流程 | 注册 → 建旅行 → 打卡 → 传照片 → 总结 → 分享 | E2E critical-path |
| 边界 | FREE 第 11 个打卡 / 第 11 张照片被拒；第 2 个未归档 FREE 旅行被拒 | 单元测试部分覆盖 ❓ |
| 边界 | 照片正好 20MB 通过、超过被拒 | E2E storage |
| 异常 | 刷新令牌失效后跳登录且不无限刷新 | E2E auth-session |
| 权限 | 访问别人的旅行 / 照片 / 视频被拒 | 单元测试；历次审计实测 |
| 状态 | 归档旅行只读；生成中视频不能删 | 单元测试部分覆盖 ❓ |
| 一致性 | 删除打卡后行程恢复 PLANNED；成就不收回 | ❓ 未确认有自动化 |
| 隐私 | 分享页不含邮箱、坐标粗化；撤销后链接失效 | 单元测试 `SharePrivacyTest` |

## 6. 缺口（已记入技术债）

- 没有连库集成测试，Mapper SQL 与迁移只能靠运行发现。
- 没有组件测试；前端交互只靠 E2E。
- 分享链接、视频生成、支付（真实 Stripe）没有 E2E。
- CI 未生效，以上检查都只能手动运行。
