# 页面布局与样式审查（2026-11-05）

本轮确认 5 类可复现的问题，优先处理平板导航遮罩，其次处理搜索弹窗和跨页面长标题。审查没有修改产品代码或部署线上版本。

后续状态：2026-11-06 已修复 L01–L05 并部署 `layout-20261106-v1`，本地及正式域名验收通过，详见 [修复验收记录](06_页面布局修复验收_2026-11-06.md)。以下保留审查时的现象与证据。

## 范围与方法

- 目标：[线上站点](https://tabi.sunows.com)，当前发布记录版本为 `map-export-20261105-v1`。
- 常规检查 76 个页面/尺寸组合：360、768、1024、1440px；长内容压力检查 33 个组合；空数据检查 22 个组合。另补查 390px 手机、844×390 横屏、860/1023px 侧栏及弹窗操作。
- 公开页面：官网、探索目录、东京探索、价格、登录、注册、找回密码、图片来源。
- 登录后页面：工作台、我的旅行、创建旅行、地图、照片、分享九宫格、视频、旅行回忆、个人资料、隐私设置、价格。
- 使用线上 HTML/CSS/JS，在浏览器内拦截业务接口并提供测试数据：两段旅行、三个打卡、十二张照片。没有读取真实账号数据，也没有向业务接口提交写入请求。
- 除综合压力数据外，额外完成 15 个“只替换旅行标题”的组合，排除了昵称、地点、打卡文字长度对标题问题的干扰。
- 自动检查页面宽度和元素边界，结合截图、真实坐标点击、`elementFromPoint` 命中结果核实。临时 CSS 只注入测试浏览器，用于验证原因。

第一轮价格页的 4 个检查因测试数据缺少 `usage.limits` 而失败；修正数据后，360/768/1024/1440px 均重新检查通过。这些测试工具错误没有计入产品问题。地图测试关闭了 WebGL，并替换了瓦片请求；截图中的“底图服务未配置”不属于本轮结论。

## 问题清单

| 编号 | 优先级 | 问题 | 触发条件与影响 |
|---|---|---|---|
| L01 | P1 | 平板侧栏被自己的遮罩覆盖 | 768–1023px 打开导航，菜单模糊且无法点击跳转 |
| L02 | P2 | 全局搜索结果行样式未匹配 | 分组结果挤成多列、箭头换行，行间距与对齐失效 |
| L03 | P2 | 横屏搜索弹窗超出可视区域 | 844×390 下，滚动结果到末尾仍无法看到最后一项 |
| L04 | P2 | 合法长旅行标题撑宽多个页面 | 分享、旅行回忆、价格，以及平板/桌面工作台和旅行列表发生横向溢出 |
| L05 | P2 | 地图时间轴照片撑宽窄屏 | 360px、多张照片的打卡记录使文档宽度变为 369px，并挤压缩略图 |

P1 表示主要入口不可正常操作；P2 表示特定内容或尺寸下影响展示与操作。以下均为已复现问题，修复建议尚未合入。

## L01：平板侧栏被遮罩覆盖

**复现：** 在 768、860 或 1023px 宽度打开“我的旅行”，点击顶部菜单按钮，再点击侧栏“创建旅行”。

**结果：** 页面仍停留在 `/trips`，抽屉关闭，没有进入 `/trips/new`。三种尺寸下，导航链接与关闭按钮中心点命中的都是 `.sidebar-scrim`。截图也可见整个菜单被模糊、压暗。

**原因：** `frontend/app/globals.css:38` 将侧栏设为 `z-index:70`，`:444` 的平板遮罩为 `75`；`:442` 的打开状态没有提升侧栏层级。`frontend/components/common/AppSidebar.tsx:88` 的遮罩覆盖全屏，拦截菜单点击。≤767px 使用底栏，不在该问题范围内。

**建议：** 统一抽屉层级，让遮罩低于侧栏，并保持侧栏高于页面内容。验收应包含真实点击导航项、关闭按钮和抽屉外区域。

[截图：平板侧栏](assets/layout-20261105/tablet-sidebar-768.png)；数据见 `details.json` 和 `title-only.json`。

## L02：搜索结果按钮样式未生效

**复现：** 打开全局搜索，保留空查询，查看旅行、地点、打卡和功能分组。

**结果：** 同一分组的多个结果并排挤在一行，箭头掉到文字下方。1440px 下，前两条旅行结果的宽度均约 211px、纵坐标相同；实际按钮为 `inline-block`、内边距为 `0`、文字居中。

**原因：** `frontend/components/common/GlobalSearch.tsx:120` 新增了分组 `div`，按钮在分组内部；而 `frontend/app/globals.css:80` 仍使用 `.command-results>button`。浏览器实测：实际有 14 个结果按钮，该选择器命中数量为 **0**。宽度、flex 对齐、内边距和 hover 规则因此失效。

**建议：** 为结果按钮设置专用 class，避免依赖它是否为直接子元素。只在浏览器把选择器改为匹配分组内按钮后，每行恢复为 602px，第二项自动排到下一行，验证了原因。

[当前截图](assets/layout-20261105/search-results-before.png) · [浏览器临时样式验证](assets/layout-20261105/search-results-selector-preview.png)。后者是修复方向预览，不是已上线效果。

## L03：搜索弹窗没有根据屏幕高度收缩

**复现：** 在 844×390 横屏打开全局搜索，将结果列表滚动到末尾。

**结果：** 弹窗顶部为 16px，高 478px，底部位于 494px，超出屏幕 104px。结果列表已经滚到底部，最后一项“Trip Pro”仍位于 `y=420–484.5px`，完全在可视区域外。

**原因：** `frontend/app/globals.css:77–81` 的弹窗未限制最大可视高度；结果列表仅使用固定 `max-height:420px`。外围全屏遮罩也没有提供可用的滚动容器。该问题在结果行样式修复前已复现，与 L02 分开处理。

**建议：** 弹窗按 `100dvh` 减去上下留白限制高度，使用纵向 flex；结果区域设置 `min-height:0` 和内部滚动。应覆盖横屏、小高度窗口和软键盘弹出后的可用高度。

[打开时截图](assets/layout-20261105/search-dialog-844x390.png) · [列表滚到底截图](assets/layout-20261105/search-landscape-scrolled-end.png)。

## L04：合法长标题缺少跨页面宽度约束

**复现：** 只将测试旅行标题替换为 `东京跨城旅行_` 加十二次 `TravelMemory_`，其他数据保持普通长度。标题总长 163 字符，低于创建页 `frontend/app/trips/new/page.tsx:135` 的 200 字符限制。

**结果：** 下表是 `document.documentElement.scrollWidth`，不是设备视口宽度；数字大于列头即代表整页横向溢出。

| 页面 | 390px | 768px | 1440px |
|---|---:|---:|---:|
| 工作台 | 390 | 1388 | 2054 |
| 我的旅行 | 390 | 1855 | 3693 |
| 分享九宫格 | 2628 | 3649 | 3862 |
| 旅行回忆 | 1597 | 1729 | 1942 |
| 价格 | 1807 | 1653 | 1958 |

移动浏览器还可能扩大布局视口，使固定底栏和整页内容缩放或超出屏幕。分享页 390px 下，标题盒宽 358px，文字自身滚动宽度为 2612px。

**代码线索：**

- 分享页 `frontend/app/globals.css:4155` 的 `.ss-head h1` 未设置长单词折行；实测 `overflow-wrap` 和 `word-break` 均为 `normal`。
- 旅行列表 `frontend/app/trips/page.tsx:55` 的两列卡片使用隐式最小内容宽度；即使最近旅行的文字已经有 `truncate`，外层列仍可被内容撑大。“继续进行”标题也缺少折行约束。
- 回忆页 `frontend/app/globals.css:2204–2205` 的精选标题、`:2256–2257` 的旅行卡片，以及 `:2285–2296` 的时间轴需要一起约束。单独裁掉精选标题无法解决时间轴造成的页面溢出。
- 价格页 `frontend/components/pro/TripStatusCard.tsx:63` 的旅行选择器显示长 option，`globals.css:3310–3312` 的容器/选择器需共同限制宽度；标题本身已经有 `overflow-wrap:anywhere`。下方 `.pr-unlocked` 也包含长旅行名，不能只修 h2。
- 工作台已确认标题单变量即可触发，具体撑宽的容器仍需在修复时进一步定位；不要只追加一条全局标题样式就视为解决。

**建议：** 完整标题区允许连续英文折行；卡片列表使用明确的省略策略；grid 列和 flex 子项补齐宽度约束。按上表逐页验收，保持 200 字符的现有输入能力。

[截图：390px 分享页](assets/layout-20261105/title-only-390-_trips_900001_share_mode_nine.png)；完整单变量测量见 `title-only.json`。

## L05：时间轴照片导致地图页面横向溢出

**复现：** 360px 宽度打开包含多张照片的打卡记录的旅行地图，向下查看旅行时间轴。

**结果：** 文档宽度为 369px，而实际可视宽度为 360px。照片列超出其正文容器，部分缩略图被压窄；移动浏览器的布局视口被扩大到 369px，底部固定操作栏也随之变宽。

**原因：** `frontend/components/map/workspace/TravelTimeline.tsx:52` 最多连续显示四张照片，并可能追加计数块。`frontend/app/globals.css:2998–3000` 使用不换行的 flex、72px 图片和间距，在窄时间轴正文中没有处理容量不足的情况。只在浏览器临时加上 `.tm-tl-photos{flex-wrap:wrap}` 后，文档宽度从 **369px 恢复为 360px**。

**建议：** 窄屏照片换行，或采用有明确边界的横向滚动容器；固定缩略图尺寸，避免不均匀压缩。应同时覆盖 1/4/5 张及更多照片、360/375/390px 和底栏宽度。

[当前截图](assets/layout-20261105/map-photo-overflow-before.png) · [浏览器换行验证](assets/layout-20261105/map-photo-overflow-wrap-preview.png)。

## 本轮未发现问题的项目与边界

- 常规公开页和空数据检查未发现整页横向溢出。
- 修正测试数据后，普通标题的价格页在四个常规宽度正常显示。
- 390×640 下，设置页未保存操作条位于底部导航上方，保存/取消按钮未被遮挡。
- 360×640 下，分享大图的关闭/原始大小按钮可见；照片详情底部操作可通过内部滚动访问，不应把首次不在屏内误判为无法访问。
- 本轮为 Windows Chromium 的桌面及移动设备模拟，未覆盖真实 iOS Safari、系统字体放大及真实软键盘；不据此宣称所有移动浏览器都已验收。
