## ADR-001：以「旅行」为核心边界，权益按旅行生效
- **状态**：Accepted（2026-10-07 起由 ADR-010 补充账号级会员）
- **日期**：2026-09-16（原《数据库设计书》）
- **背景**：打卡、照片、成就、分享、视频、支付都需要一个归属单位。
- **决策**：所有业务数据挂在 `trips` 下；FREE / PRO 由 `trips.plan_type` 决定，不做用户全局会员。统计和成就进度实时计算，只持久化「获得成就」。
- **原因**：付费意愿对应「一次旅行的成果」；按旅行计费门槛低。
- **影响**：归属校验统一走 `TripService`；终身 Pro 的实现方式是把账号下所有旅行设为 PRO。

## ADR-002：视频渲染用独立 Worker + 数据库队列
- **状态**：Accepted
- **日期**：2026-09-15（原技术书 §23、§24）
- **背景**：渲染 CPU / 内存消耗高、耗时长，失败重试与 API 生命周期不同。
- **决策**：独立进程 `video-worker`，以 `video_projects.status=QUEUED` 作为队列，Worker 轮询并用条件更新抢占；API 内置看门狗处理中断。不引入 Kafka / RabbitMQ。
- **替代方案**：消息队列（等真实视频量证明需要时再引入）；Remotion（未采用，改为 Java2D + FFmpeg）。
- **影响**：API 与 Worker 只通过数据库和存储交换数据；改 `video_projects` 结构要同时改 Worker SQL。

## ADR-003：Travel Story 生成时冻结分镜
- **状态**：Accepted
- **日期**：2026-09-21
- **决策**：点「开始生成」时重新校验全部条件，把分镜（含音乐片段）写入 `storyboard_json`，Worker 只按它渲染；已生成的项目不能直接改，「重新编辑」复制出新草稿。
- **原因**：预览与成片是同一份数据，结果可复现；生成过程中用户改设置不影响正在渲染的任务。
- **影响**：`StoryboardService`、`VideoService`、Worker `FfmpegRenderer`。

## ADR-004：访问令牌放内存，refresh token 放 HttpOnly Cookie
- **状态**：Accepted
- **日期**：未记录（2026-10-06 审计前已实现，依据 `services/api.ts` 注释）
- **决策**：访问令牌 15 分钟、只在页面内存；refresh token 30 天、HttpOnly + SameSite=Strict 的 `tt_refresh`，每次刷新轮换；localStorage 只存「登录过」标记。访问令牌带会话 id，退出即失效。
- **原因**：XSS 读不到凭证；生产同源代理下 Cookie 是第一方，Safari 不拦截。
- **替代方案**：令牌存 localStorage（旧版本做法，已迁移掉）。

## ADR-005：邮箱验证码注册；限流用 MySQL，不引入 Redis
- **状态**：Accepted
- **日期**：2026-09-26
- **决策**：注册、找回密码都需要邮箱验证码；验证码与令牌只存哈希；发送频率和登录失败限流用 `email_verifications`、`login_failures` 表计数。
- **原因**：MVP 不增加基础设施。
- **影响**：多实例部署时限流仍然准确（数据库共享）。

## ADR-006：部署到 Railway，采用「网页同源代理 + 私网 API」
- **状态**：Accepted
- **日期**：约 2026-09-27（依据 `deploy/RAILWAY.md` 修改时间）
- **决策**：只有 web 对公网开放；浏览器访问同源 `/api/v1`，Next.js rewrites 转发到私网 API；API 按 `X-Forwarded-For` 最右侧取客户端 IP。
- **原因**：不需要 CORS；refresh Cookie 是第一方；API 不暴露公网。
- **替代方案**：原技术书的 Amazon Lightsail + Nginx 单机方案（`backend/deploy/` 里的示例为遗留，不再使用）。

## ADR-007：生产环境不使用 OpenStreetMap 官方瓦片
- **状态**：Accepted
- **决策**：生产必须配置底图服务商；没有配置时地图只显示标点，构建日志警告。开发环境可以回退 OSM 官方瓦片。
- **原因**：OSM 瓦片使用政策不允许商业流量。
- **影响**：`lib/map-tiles.ts`、`next.config.ts`。

## ADR-008：定价——Trip Pro ¥4 / 段旅行 + 终身 Pro ¥1000
- **状态**：Accepted（与 MVP 计划书冲突，**❓ 待用户最终确认**）
- **日期**：终身 Pro 2026-09-29（V13）；Trip Pro 从 ¥1.1 调到 ¥4 在 10-06 审计之后（第二阶段，用户定价）
- **背景**：MVP 计划书建议 ¥490；¥1.1 低于 Stripe 最低收款额无法收款。
- **决策**：Trip Pro 400 分（CNY），一次性、不续费不过期；终身 Pro 100000 分，账号下所有旅行 PRO 并开通会员。数值只在 `PaymentService` 定义，经 `GET /plans/trip-pro` 下发。
- **影响**：改价格只改后端常量。

## ADR-009：音乐库精选；「无音乐」用 NULL；音乐失败降级
- **状态**：Accepted
- **日期**：2026-10-07（V14）
- **决策**：只启用 19 首授权清楚的 CC BY 4.0 曲目（FREE 8 / PRO 11，5 个氛围分类）；`music_code=NULL` 表示无音乐（不再用伪记录）；音乐文件不可用时成片改为无音乐而不是失败；曲目授权记录完整入库，音频放自己的存储，不外链。
- **原因**：减少选择负担；避免伪数据；版权可追溯。

## ADR-010：会员（账号级）与 Trip Pro（旅行级）分开
- **状态**：Accepted
- **日期**：2026-10-07（V15）
- **决策**：新增 `memberships`。Trip Pro 负责 1080p、60 秒、去水印、更多素材（按旅行）；会员负责上传自定义音乐（按账号）。目前只有买断终身 Pro 会开通会员；表结构支持以后的订阅（`expires_at`）。
- **影响**：`MembershipService.require` 是会员功能的唯一后端判断；前端用 `MembershipGate`。

## ADR-012：官方景点图统一为 Wikimedia Commons 高清 4 档 WebP
