# 操作体验评审与改版方案（2026-11-06）

建议把旅迹的主要界面围绕「正在记录哪趟旅行、下一步做什么」组织。保留暖色、实景照片和旅行记忆的气质，让首页、导航和按钮更直接地服务于记录、整理和导出。

11月6日完成体验分析和交互方案，当时线上基线为 `layout-20261106-v1`。2026-11-08用户选择桌面旅行工作台后，核心改版已发布为 `usability-20261108-v3`，正式域名464项检查通过；范围与截图见[改版验收](../08_testing/07_旅行工作台改版验收_2026-11-08.md)。下方保留分析时的发现与分阶段建议，不代表所有后续建议均已实现。

## 评审依据与边界

- 检查当前源码，并在正式域名以 1440×1000、390×844 两种尺寸查看首页、旅行列表、创建旅行、地图、照片、分享、设置和回忆，另查看快速打卡面板。
- 登录与旅行数据仅在测试浏览器内注入；没有读取真实账号或向业务接口提交写入请求。
- 旅行视频的两次截图因测试会话无法访问模板接口而显示登录失败，未作为产品缺陷证据。视频流程依据源码分析，保留其现有分步设计。
- 图片使用测试素材；地图主动关闭 WebGL。因此不评价素材清晰度或截图中的基础地图缺失提示。
- 结论来自界面检查、实际尺寸测量及可用性原则，尚未经过真实用户任务测试，不宣称点击次数或操作效率已经提高。

## 主要发现及建议

| 优先级 | 当前表现 | 对操作的影响 | 改版建议 |
|---|---|---|---|
| 高 | 全局侧栏同时列出首页、旅行、创建旅行，以及某趟旅行的地图、照片和视频 | 全局内容与单趟旅行内容混在一起，用户需要记住这些入口对应哪趟旅行 | 全局导航收拢为首页、我的旅行、探索、旅行回忆；进入旅行后统一显示旅行名称、切换入口，以及地图/行程、照片、导出分享、视频 |
| 高 | 首页欢迎区有「继续记录」「进入旅行」两个按钮，实际都去同一个地图地址；当前旅行卡片又重复提供地图入口 | 相近按钮没有说明操作差别；重要信息被重复入口分散 | 首页优先展示当前旅行、下一站、今日记录；主操作明确为「记录这一刻」，地图和照片各保留清楚的次入口 |
| 高 | 手机首页「当前旅行」标题约在 y=651px；地图页时间轴标题约在 y=1527px | 在 844px 高的屏幕上，欢迎图、统计、地图和操作栏先占据空间，记录内容需要继续向下寻找 | 缩小欢迎区；地图与行程列表可切换；优先显示下一站和今日记录，而不是把地图、列表和时间轴全部纵向堆叠 |
| 高 | 手机地图底部同时有「添加地点 / 快速打卡」固定栏和全局凸起相机按钮 | 两层操作区竞争注意力并占用内容空间 | 保留全局记录入口；「添加地点」放入行程列表标题栏，页面不再叠加第二层固定打卡栏 |
| 高 | 九宫格已经自动显示照片，素材栏计数却只统计手动选中的照片；初始可能显示「0/9 已选」 | 容易把「未手动选择」理解为「没有照片」，不清楚能否导出 | 改成「已填9/9格 · 自动9张 · 手动0张」；不足时显示「已填8/9格，保留1空位」，仍允许导出 |
| 高 | 390px 分享页的素材编辑标题约在 y=845px，分享链接约在 y=2440px；导出按钮先于编辑材料出现 | 用户可能先导出，再发现可以换照片；修改时需要在预览与素材间反复滚动 | 手机采用「选择照片 → 预览样式 → 导出」；选格后在邻近抽屉中替换，保持当前格提示；电脑保留预览和素材并排 |
| 中 | 照片页同时出现精选说明、四类筛选、分组、排序、选择、浮动添加和卡片图标 | 首屏需要理解多组控制；照片本身和常用操作不够突出 | 默认显示全部/精选与清楚的「添加照片」「选择」；其他筛选与排序收进筛选面板；一个精选状态只保留一个清晰的操作标记 |
| 中 | 创建旅行的手机预览先于表单；「这次要去哪里」约在 y=545px，日期段约在 y=812px | 用户先滑过预览和说明，才开始填写；创建动作显得比实际复杂 | 先目的地和日期，继续使用现有自动命名；人数与标题修改就近收纳；预览和自动准备说明折叠，不再占据填写前的主要空间 |
| 高 | 部分正常启用的主按钮为白字、`#E97A33` 背景，实测文字为13–15px；对比度约2.88:1 | 在光线强或视力较弱时，按钮文字更难读 | 主按钮用更深的暖橙色；例如白字配 `#B54C1E` 约5.23:1。统一重要正文、辅助文字和触摸区域，不以低对比度表达所有次要信息 |

普通大小文字的 AA 对比度要求为至少4.5:1，较大文字为3:1；这里测量的主按钮文字属于前者。[W3C：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

导航清楚地显示当前旅行、让用户根据可见信息选择下一步，以及减少重复功能入口，符合「系统状态可见」「识别优于记忆」「界面简洁」等可用性原则。以上是针对现有界面的应用判断，不是用户访谈结论。[NN/G：界面可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)

## 建议的页面组织

### 全局与旅行分开

桌面全局导航：**首页 / 我的旅行 / 探索 / 旅行回忆**。创建旅行作为旅行列表的操作按钮；账户与设置集中在个人菜单；Pro 信息在相关能力需要说明时出现。

手机建议：**首页 / 旅行 / 记录 / 探索 / 我的**。分享入口放在当前旅行内，避免全局「分享」按钮隐含指向最近访问的某趟旅行。如果实际使用中导出频率明显高于探索，可以保留分享快捷入口，但应先显示对应的旅行名称。

单趟旅行始终显示名称、日期、状态和切换入口。已有地图、照片、分享、视频路由可保留，调整它们的入口和页面标题即可，不必先合并业务接口。

### 首页先回答三个问题

1. **我正在记录哪趟旅行？** 显示旅行名和日期，能切换，不用先读欢迎文案。
2. **接下来去哪？** 显示下一站、计划时间，以及导航和到达打卡。
3. **刚才保存了什么？** 显示今日时间轴与最近照片，保存后就近出现新记录。

问候语缩为一行。统计保留为简短摘要；完整日历和历史动态进入次级区。已有旅行时突出继续记录；没有旅行时，首页只突出创建第一段旅行和一个简短示例。

### 把不同导出任务说清楚

在旅行内提供「导出与分享」，首先按用途选择：

| 用途 | 对应能力 | 操作前应说明 |
|---|---|---|
| 保存旅行记录 | PDF / PNG / JPG / CSV，沿用地图联合导出 | 整趟/某天、照片是否包含；PDF/图片可带地图，CSV是文字表格 |
| 制作图片作品 | 城市海报 / 九宫格 / 每日长图 | 当前模板、已填照片数量、空位、整张或单格导出 |
| 发送访问链接 | 现有分享链接 | 谁能看、有效期与位置显示规则；删除链接后访问失效 |

普通用户先看到推荐默认值，高级选项按需展开。导出过程中持续显示进度，完成后给出下一步，失败时保留所选材料。

分享链接目前部分规则来自账户隐私设置。第一阶段先在创建前展示当前规则并提供就近修改入口；如果要逐链接覆盖权限，需要核对现有接口能力，不能只做一个不生效的前端开关。

### 保留现有顺手的行为

- 快速打卡已有「记录到哪趟旅行」、拍照/相册、选填备注、自动时间地点、折叠修改和保存成功反馈，保留这些能力。
- 当前日期不在旅行范围时，现有逻辑会调整到旅行期间。应把调整原因和最终保存日期放在保存按钮附近，方便用户确认。
- 九宫格照片不足时继续留空，不重复补照片；不要把「凑够九张」变成导出门槛。
- 归档旅行继续明确显示只读状态；用户看回忆时，不应误以为仍在向该旅程添加记录。
- 视频页已经有模板、素材、风格、设置/导出和生成步骤，其他编辑页面可参考这一结构。

## 视觉与反馈规则

| 内容 | 建议 |
|---|---|
| 整体风格 | 保留暖白背景、旅行照片和橙色重点；减少大面积欢迎图、重复阴影和多层卡片包裹 |
| 字号 | 正文以15–16px为主要参考，手机输入框16px；辅助文字优先13–14px。小英文标签只作装饰，不承担操作说明 |
| 按钮层级 | 当前任务一个主色操作，其余用次按钮或文字入口。不同文字应对应不同结果，合并同目标的重复按钮 |
| 触摸 | 高频独立操作优先提供约44×44px的有效点击区，图标本身可更小；不要让相邻精选、更多和相机入口挤在一起 |
| 保存反馈 | 在原位置更新照片/时间轴，并显示保存到哪趟旅行；重要结果不能只依赖短暂 toast |
| 出错 | 保留已填内容，说明能否重试；定位失败仍应允许手动填写，而不是让整个记录流程无法继续 |
| 删除与撤销 | 统一确认界面并说明影响；删除链接、撤销打卡、移除计划使用具体措辞。真正的恢复能力需后端支持，不能只显示一个无法恢复的「撤销」按钮 |

44×44px是本方案对高频触摸操作的设计目标；WCAG 2.2 AA 的最低目标尺寸是24×24px，且存在间距等例外，不应把所有小于44px的控件直接判为不合规。[W3C：目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## 分阶段实施

| 阶段 | 改动 | 验收重点 |
|---|---|---|
| 首批：减少困惑 | 修正九宫格计数文案、合并首页同目标按钮、明确当前旅行、提高按钮对比度、减少手机双层固定操作区 | 不会选错旅行，知道照片是否已填入，知道点击后会发生什么 |
| 第二批：重排主要页面 | 首页以当前任务为中心；地图/行程列表切换；照片控件收纳；创建表单前移 | 首屏出现当前旅行与下一步，不必先滑过大量装饰或说明才能操作 |
| 第三批：整理成果流程 | 分享分步编辑、统一导出入口、创建链接前展示隐私、完善草稿与失败恢复 | 选材后能连续预览与导出，失败不丢选择，清楚访问链接的范围 |

实现时优先复用 `SiteHeader`、`PageContainer`、`LiveTripSubnav` 和现有导出、打卡组件。先统一颜色、字号、间距和按钮状态，再调整具体页面，避免继续向各页追加不同的样式规则。

## 可操作预览与验证

预览提供「桌面旅行工作台」「手机随手记录」两种视图，可切换行程/照片/导出，打开记录面板、填写示例地点并保存到演示时间轴，也可检查CSV与九宫格空位行为。预览不连接业务接口；其中的保存、生成和分享均为演示反馈，不表示已经写入线上。

预览完成11项检查：1024/736/320px宽度、桌面与手机切换、记录面板、填写后的时间轴更新、CSV不含地图、九宫格8张照片保留1空位、320px导出显示、主按钮颜色及无运行错误。还检查了深色显示。

后续应在测试环境用明确任务验收，而不只检查截图：创建一段旅行、向正确旅行保存记录、替换九宫格第5张、导出带地图PDF、查看链接访问范围。记录用户停顿、返回寻找入口和是否需要旁人解释，再决定是否继续收拢导航或保留快捷入口。
