# Git 版本管理规范

## 1. 仓库

- 远程：`https://github.com/SUN1105-QC/TabiTrace.git`，单仓库（frontend、backend、e2e、docs 在一起）。
- 分支：目前只有 `main`，没有开发分支或发布分支；也没有 Tag 和 Release。

## 2. 提交与推送（用户要求，必须遵守）

- **只有用户明确认可（「没问题 / 可以提交 / 传到 git」）之后才能 commit 和 push。** 改完先汇报、等验收，不要自动提交，也不要顺手推送（ADR-014）。
- 汇报改动时在末尾说明「尚未提交，确认没问题后再推送」。
- 推送前检查不带上：日志、构建产物（`.next`、`target`）、成片（`frontend/public/generated-videos`）、上传文件（`.tabitrace/`）、本地工具（`.tools/`）、任何 `.env`（只提交 `*.example`）。`.gitignore` 已覆盖这些，但仍要看一遍待提交清单。
- 大批量改动建议按层或按功能分批提交，让每个提交都能单独构建、可回滚。

## 3. 提交说明

- 中文，第一行概括这次改了什么（例：`旅迹功能迭代：邮箱验证码注册、登录注册重构、首页与各工作台重做`）。
- 由 AI 生成的提交在末尾加署名行（按当时环境给出的格式）。
- 不提交空提交，不使用 `--no-verify` 跳过钩子。

## 4. 换行与二进制

`.gitattributes`：仓库内统一 LF，检出时按平台转换；`.bat` / `.cmd` 保持 CRLF；图片、音频、视频按二进制处理。提交时出现「LF will be replaced by CRLF」警告属正常。
