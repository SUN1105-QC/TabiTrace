# 数据库设计

**最终事实是迁移文件** `backend/api/src/main/resources/db/migration/V1–V22`；本文解释设计意图、关系和约束。字段的业务含义见 [数据字典](02_数据字典.md)，状态取值见 [枚举与常量](03_枚举与常量定义.md)。V20–V22 为 2026-10-28 / 29 本地新增，尚未发布到生产。
（2026-10-13 核对：本地库 `flyway_schema_history` 到 V19，24 张业务表。原《数据库设计书 v1.0》只覆盖 V1–V2，已删除，可从 Git `c6adb8d` 找回。）

## 1. 基本约定

| 项目 | 约定 |
|---|---|
| 数据库 | MySQL 8（目标 8.4 LTS），InnoDB，`utf8mb4` / `utf8mb4_0900_ai_ci` |
| 主键 | `BIGINT AUTO_INCREMENT`（例外：`video_templates`、`video_music` 用 `code` 作主键；`place_favorites` 用 `(user_id, place_id)` 联合主键） |
| 命名 | 表名、列名 snake_case，表名复数 |
| 时间 | 事件时间以 UTC 存 `DATETIME(6)`，SQL 里用 `UTC_TIMESTAMP()`；旅行起止 `DATE`；行程 `planned_time` 用 `TIME` |
| 状态 | `VARCHAR` + 默认值，**没有 ENUM / CHECK**，合法值由代码校验 |
| 二进制 | 照片、视频、音乐不进数据库，只存 `storage_key`（存储路径）和访问 URL |
| 变更 | 只能通过新的 Flyway 迁移；**已执行的迁移文件不能修改**（包括注释，校验和会变）；原则上只做加法 |

## 2. 表与关系

```
users ─┬─< refresh_tokens（登录会话）
       ├─< memberships（会员）
       ├─< user_music（我的音乐）
       ├─< place_favorites >── places
       ├─< payments（user_id / trip_id 删除时置空）─< payment_events（渠道事件去重）
       └─< trips ─┬─< trip_places >── places ──< official_cities 按城市名关联（无外键）
                  ├─< itinerary_items ──(place_id 置空)── places
                  ├─< checkins ──(place_id、itinerary_item_id 置空)
                  ├─< photos ──(checkin_id 置空)── checkins
                  ├─< share_links
                  ├─< user_achievements >── achievements
                  └─< video_projects ─< video_project_photos >── photos
                                      └── video_templates / video_music（按 code，无外键）

独立表：destinations（目的地参考数据）、official_routes（专题路线，place_ids 存逗号分隔的 id）、
        email_verifications、login_failures（限流与验证，按 email / IP 哈希查询，无外键）
```

| 分组 | 表 | 迁移 |
|---|---|---|
| 账号 | `users`、`refresh_tokens`、`email_verifications`、`login_failures`、`memberships` | V1、V6、V8、V9、V13、V15、V17、V19 |
| 旅行 | `trips`、`trip_places`、`itinerary_items`、`checkins`、`photos` | V1、V11、V12 |
| 地点与内容 | `places`、`official_cities`、`official_routes`、`place_favorites`、`destinations` | V1、V2、V4、V5、V7、V18 |
| 成果 | `achievements`、`user_achievements`、`share_links` | V1、V2 |
| 付费 | `payments`、`payment_events`；`users` / `trips` 保留赠送权益标记 | V1、V13、V17、V20 |
| 视频与音乐 | `video_projects`、`video_project_photos`、`video_templates`、`video_music`、`user_music` | V1、V3、V10、V14、V15、V16 |
| 成本观测 | `cost_control_locks`、`render_usage_daily`、`cost_alerts`；`video_projects.output_bytes` | V21 |
| 成片清理 | `video_output_deletions`；不设置外键，项目、旅行及账号删除后继续保留待清理任务 | V22 |

## 3. 删除策略

| 删除对象 | 结果 |
|---|---|
| 用户（注销到期） | 级联删除会话、会员、我的音乐、收藏、旅行及旅行内全部数据；`payments.user_id` 置空（保留支付记录）；`AccountDeletionService` 先删账号存储目录，同事务登记视频清理任务，补清本地成片或残留标准路径 |
| 旅行 | 级联删除 `trip_places`、行程、打卡、照片记录、分享链接、成就记录、视频项目；`payments.trip_id` 置空；删除前同事务登记所有项目的成片清理任务 |
| 地点 | 级联删除 `trip_places`、收藏；行程和打卡的 `place_id` 置空（打卡保留名称快照） |
| 打卡 | 照片的 `checkin_id` 置空（照片保留） |
| 照片 | 级联删除 `video_project_photos`；代码同时清除引用它的视频封面和旅行封面 |
| 视频项目 | 级联删除 `video_project_photos`；同事务登记成片清理任务，Worker 删除文件成功后才清除任务 |

逻辑删除只有两处：`user_music`（`status=DELETED` + `deleted_at`，存储文件清理后记 `purged_at`）和用户注销冷静期（`status=DELETION_PENDING`）。

## 4. 唯一约束与索引（要点）

| 约束 / 索引 | 作用 |
|---|---|
| `users.email` UNIQUE | 邮箱唯一（并发注册以此为准） |
| `trip_places(trip_id, place_id)` UNIQUE | 地点在一段旅行里只出现一次 |
| `user_achievements(user_id, trip_id, achievement_id)` UNIQUE | 同一成就每段旅行只获得一次 |
| `share_links.share_token` UNIQUE、`refresh_tokens.jti` UNIQUE、`email_verifications.token_hash` UNIQUE | 令牌唯一 |
| `payments.provider_payment_id` UNIQUE | Webhook 幂等 |
| `video_project_photos(video_project_id, photo_id)` UNIQUE | 视频照片不重复 |
| `idx_video_queue(status, id)` | Worker 领取任务 |
| `idx_checkins_trip_time`、`idx_photos_trip`、`idx_itinerary_trip_date` | 时间轴、照片墙、行程按时间查询 |
| `idx_email_verifications_lookup / _ip`、`idx_login_failures_email / _ip` | 限流计数 |
| `idx_users_deletion(status, deletion_scheduled_at)` | 注销到期扫描 |
