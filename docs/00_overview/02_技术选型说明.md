# 技术选型说明

版本以 `frontend/package.json`、`backend/pom.xml` 为准（2026-10-13 核对）。理由来自原《项目技术书 v3.0》（09-15，已删除，可从 Git `c6adb8d` 找回）和代码注释；找不到依据的标 `❓`。

总原则（技术书）：**简单、稳定、熟悉、低成本、可维护、可扩展**，不因新增视频和分享能力而提前引入复杂架构。

## 选型清单

| 领域 | 选择 | 用途 / 理由 | 替代方案与约束 |
|---|---|---|---|
| 前端框架 | Next.js 16.3.3（App Router）+ React 19.2 + TypeScript 5.7（strict） | 页面路由、SEO 元数据、生产时用 rewrites 做同源 API 代理 | ⚠ Next 16 有不兼容改动，写代码前读 `frontend/AGENTS.md` |
| 样式 | Tailwind CSS 3.4 + `app/globals.css` | 主题色与布局类 | 没有 UI 组件库，组件都是自写 |
| 地图 | MapLibre GL 6.10（WebGL）+ Leaflet 1.9（无 WebGL 时） | 开源、可接任意底图服务商 | 生产不使用 OSM 官方瓦片（见 ADR-007） |
| 分享图 | html-to-image | 在浏览器里把 DOM 导出 PNG，服务端不需要渲染 | 导出规格由后端方案配置下发 |
| 动画 / 图标 | framer-motion（只在视频预览）、lucide-react | — | — |
| 前端测试 | Vitest 3（纯逻辑单测） | 轻量 | 技术书计划的 React Testing Library、Playwright 未采用；E2E 用自研 CDP 脚本 |
| 后端框架 | Java 21 + Spring Boot 4.1.1（webmvc、security、validation、actuator、mail） | 团队熟悉，生态完整 | — |
| 数据访问 | MyBatis 4.1（注解式 Mapper） | SQL 可控、简单 | 没有使用 JPA ❓（选择原因未记录） |
| 数据库 | MySQL 8（目标 8.4 LTS），Flyway 管理迁移 | 熟悉、低成本；所有结构变化只走迁移 | 本地实测 8.0.46；不使用多数据库、MongoDB |
| 认证 | JWT 访问令牌（JJWT 0.12.6）+ refresh token（HttpOnly Cookie，数据库存会话）+ BCrypt | 无状态 API，同时能撤销会话 | 见 ADR-004 |
| 对象存储 | Cloudflare R2（AWS SDK v2 S3）；开发用本地磁盘 | 照片 / 视频不进数据库，只存 key 和 URL | 见 [文件存储设计](../06_backend/04_文件存储设计.md) |
| 视频渲染 | 独立 Worker 进程 + FFmpeg（画面用 Java2D 绘制） | CPU / 内存消耗高、耗时长、失败重试与 API 生命周期不同，所以必须独立进程 | 技术书写的 Remotion 未采用；任务队列用数据库表（见 ADR-002） |
| 邮件 | Spring Mail（SMTP）或 Resend HTTPS API | Railway 非 Pro 套餐不允许出站 SMTP，所以加了 Resend | 本地用自带的邮件接收器 |
| 支付 | Stripe Checkout + Webhook（REST 直接调用，没有引 SDK） | 支付结果以服务端 Webhook 为准 | 价格低于 Stripe 最低额时无法收款（当前 ¥4 正好等于默认最低额） |
| 逆地理 / 天气 | Nominatim、Open-Meteo | 免费、无需 Key | ⚠ 条款不适合商用（P1） |
| 部署 | Railway（web / api / worker / MySQL） | 同源代理 + 私网 API（见 ADR-006） | 技术书原计划 Amazon Lightsail + Nginx，已不采用 |

## 明确不引入（技术书 §52，至今仍成立）

Kubernetes、微服务、Kafka / RabbitMQ、Elasticsearch、Redis（含集群）、Service Mesh、GraphQL、MongoDB、多数据库架构。
视频任务用数据库队列；只有真实视频生成量证明需要时再引入消息队列。频率限制也用 MySQL 表实现，不引入 Redis（见 ADR-005）。
