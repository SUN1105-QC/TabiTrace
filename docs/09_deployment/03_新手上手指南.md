# 新手上手指南（从 0 在本机跑起来）

目标：第一次接触项目的开发者，在 Windows 本机把整套服务跑起来并通过检查。（项目目前只在 Windows 上实际使用过；macOS / Linux 需要自行改用等价命令 ❓）

## 1. 准备

| 软件 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 20.9 | 实测 v25.1.0 |
| JDK | 21 | 实测 21.0.4 |
| Maven | 3.9 | 项目没有 Maven Wrapper |
| MySQL | 8.x | 实测 8.0.46；也可用 `backend/docker-compose.yml` 起 `mysql:8.4` |
| FFmpeg | 可选 | 生成真实视频才需要：`winget install --id Gyan.FFmpeg -e`（装完重开终端） |
| Chrome / Edge | — | 跑 E2E 需要 |

## 2. 初始化数据库（只做一次）

用 MySQL 管理员账号执行，创建 `tabitrace` 库和 `tabitrace_app` 账号（本地开发密码见脚本，仅限本机）：
```bash
mysql -u root -p -e "source backend/scripts/mysql-init-local.sql"
```
表结构和东京官方内容由 API 第一次启动时 Flyway 自动创建，不需要手工建表。

## 3. 启动

**最省事**：双击根目录 `启动TabiTrace前后端.bat`（依赖仓库内的 `backend/scripts/start-local.ps1`）。它会：

- 检查 Node.js / Java / npm / mvn 是否可用；
- 按 `FFMPEG_BINARY` → PATH → `.tools/ffmpeg` → winget 目录查找 FFmpeg：找到就启动视频 Worker 并关闭 API 的 Mock 渲染器，找不到就只用 Mock（视频能走流程但不能播放）；
- 启动开发邮件接收器（SMTP 1025，查看页 http://127.0.0.1:1080；`MAIL_HOST` 已设置时跳过，两个默认端口都已监听时复用）；
- 在后台启动 API，等待健康检查及数据库迁移完成后再启动 Worker；前端依赖不存在时先 `npm ci`，固定使用 3000 端口；
- 检查首页成功响应后显示 `[READY]`，已有服务健康时复用；启动失败或端口被其他服务占用时报告错误并保留窗口；
- 把服务输出保存到 `backend/.tabitrace/local-dev/` 中的 `api.log`、`worker.log`、`frontend.log`、`mail.log` 及各自的 `.err.log`，关闭启动器窗口后服务继续运行。

**手动**：
```bash
node backend/scripts/dev-mail-catcher.mjs                       # 邮件接收器
mvn -f backend/pom.xml -pl api spring-boot:run                  # API → http://localhost:8080/api/v1
cd frontend && npm install && npm run dev                       # 前端 → http://localhost:3000
STORAGE_MODE=local mvn -f backend/pom.xml -pl video-worker spring-boot:run   # 视频 Worker（API 需 VIDEO_MOCK_RENDERER=false）
```

⚠ 用 AI 工具（或其他会被回收的后台作业）拉起服务时，服务会随作业一起退出；需要用独立进程启动脚本（Windows 上用 WMI：`Invoke-CimMethod Win32_Process Create` 执行启动脚本）。

## 4. 验证

1. 打开 http://localhost:3000，注册一个 `*@example.test` 测试邮箱，在 http://127.0.0.1:1080 查看验证码。
2. 跑检查（见 [测试计划](../08_testing/01_测试计划.md)）：
   ```bash
   cd frontend && npm run typecheck && npm run lint && npm run test
   mvn -B -f backend/pom.xml test
   ```
3. 需要时跑 E2E：`cd frontend && npm run test:e2e`（部分套件需要测试账号，见 `e2e/README.md`）。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 地图只有底色 | 本地开发会回退 OSM 瓦片，需要能访问外网；生产必须配置底图服务商 |
| 视频完成但不能播放 | 用的是 Mock 渲染器（地址是 `example.invalid`）；安装 FFmpeg 后重启 |
| 视频一直排队 | Worker 没启动，或 API 的 Mock 渲染器与 Worker 抢任务（跑 Worker 时 API 必须 `VIDEO_MOCK_RENDERER=false`） |
| 执行 `npm run build` 后页面不显示数据 | 重启 3000 端口的开发服务器（开发产物在 `.next/dev`，生产产物在 `.next`，早期版本曾互相影响） |
| 3000 / 8080 被占用 | 不要直接结束别人的进程；改用 3001 / 8081（见 [环境与配置](01_环境与配置说明.md) §4） |
| 生产构建报 APP_URL 错误 | `next build` 要求 https 的 `APP_URL`，本地验证用 `APP_URL=https://tabitrace.example` |
| 收不到验证码 | 确认邮件接收器在 1025 端口运行；SMTP 不可用时接口如实返回 503 |
