# 成本保护与监控

更新于 2026-10-30，已随 f32c4aa 发布至生产。Flyway 已升级到 V22，API、Worker、前端同步更新。

## 默认行为

用户于 2026-10-29 明确选择启用限额，项目默认配置现为 `COST_ENFORCE=true`：单账号每日 20 次生成请求、累计目标成片时长 6000 秒、全站同时排队/生成最多 3 个任务。价格及照片/打卡权益不变。

数值已同步到 [限额启用配置](../../deploy/lightsail/.env.cost-limits.example)、通用示例、Spring 配置和 Compose。显式设置 `COST_ENFORCE=false` 可退回只观测模式。0 表示对应维度不限；至少一项视频限额必须为正数，否则启用时拒绝启动。生产受限 `.env` 已明确写入启用开关、20 次、6000 秒及全站 3 个任务，其余密钥保留；后续调整配置须重新创建 API 容器。

已有的「每账号同时最多两个视频」继续执行；新版本通过数据库锁串行化提交检查，消除并发请求同时绕过检查的窗口。

| 环境变量 | 默认 | 用途 |
|---|---:|---|
| COST_ENFORCE | true | 启用视频预算拦截 |
| COST_ACCOUNT_DAILY_RENDERS | 20 | 单账号每日生成请求上限 |
| COST_ACCOUNT_DAILY_SECONDS | 6000 | 单账号每日累计成片时长上限（秒） |
| COST_GLOBAL_DAILY_RENDERS | 0 | 全站每日生成请求上限 |
| COST_GLOBAL_DAILY_SECONDS | 0 | 全站每日累计成片时长上限（秒） |
| COST_GLOBAL_ACTIVE_RENDERS | 3 | 全站排队/生成中任务上限 |
| COST_WARN_DAILY_RENDERS | 20 | 单账号生成次数告警阈值 |
| COST_WARN_DAILY_SECONDS | 1200 | 单账号累计成片时长告警阈值 |
| COST_WARN_GLOBAL_DAILY_RENDERS | 200 | 全站生成次数告警阈值 |
| COST_WARN_GLOBAL_DAILY_SECONDS | 12000 | 全站累计成片时长告警阈值 |
| COST_WARN_STORAGE_BYTES | 10737418240 | 单账号登记媒体估算告警阈值（10 GiB） |
| COST_SCAN_INTERVAL_MS | 900000 | 每批存储观测间隔（15 分钟） |
| COST_SCAN_BATCH_SIZE | 100 | 每批账号数量（上限 500），循环扫描 |

`COST_WARN_*` 是观察阈值；启用时正数预算项才是硬限额。它们都不是价格、实际云账单预测或额外收费。告警写 `cost_alerts`，日志以 `COST threshold` 开头，同一统计日/账号（或全站）/资源只记录一次，不发送站外消息。购买页从方案接口读取账号额度，未登录访客也能在购买前看到限制。

Compose 已显式映射这些变量。填写服务器受限 `.env` 后须重新创建 API 容器才生效；本地 Maven 不会自动读取 `.env`，须把变量放进启动进程环境。

## 计数与并发

统计日按 UTC 划分（日本时间每天 09:00 重置）。每次通过全部校验并成功入队后，在同一事务内增加请求次数和目标成片秒数。

- 校验失败、入队竞争失败、预算不足：整体回滚，不增加计数、不留下错误队列状态。
- 生成后失败再手动提交：新请求计一次；已提交后删除项目：不退还当日计数。
- Worker 内部因停机恢复同一排队任务：不额外增加 API 请求计数。
- 次数与目标时长是工作量指标，不等于 FFmpeg 的实际 CPU 时间或货币成本。
- 历史项目不能可靠重建已经删除的请求，计数从 V21 启用后开始。

账号行锁和永久全站锁覆盖提交检查及用量预留。限额启用后超额返回 429 / `VIDEO_DAILY_BUDGET` 或 `VIDEO_GLOBAL_QUEUE_LIMIT`，响应包含 `Retry-After`。不是付款失败，不会触发额外扣费。

## 存储统计边界

`GET /api/v1/users/me/usage` 只返回当前登录账号；升级页「账号用量」展示此结果。

估算包括照片已登记原图大小、缩略图/中图按上传上限的保守估算、音乐尚未清理的预留空间、Worker 新记录的视频成片实际字节数。历史照片大小缺失与旧视频未计量分别返回数量，不把未知文件冒充已测量的零字节。

这不是对象存储账单或桶清单：不覆盖未登记上传、头像、已删除数据库记录但仍遗留的对象；照片大小仍以登记数据为基础，不能当成经过 HEAD 校验的实际字节。因而本轮不对存储估算实施硬容量限额，不因用量告警删除用户数据。用户主动删除视频/旅行、账号注销到期时，新版会登记 V22 成片清理任务，失败重试，详见 [文件存储设计](../06_backend/04_文件存储设计.md)。待清理文件及历史孤儿仍不在账号估算内。未来若需精确账号总容量，先补对象元数据核验、上传预留账本和存储清单对账。

## 验证与运维检查

`mvn verify` 的成本测试检查默认启用 20 次 / 6000 秒 / 全站 3 个任务、启用但全部限额为零时拒绝启动、显式只观测模式、正数/零值含义、精确额度边界、UTC 重置与重试时间。`MySqlPaymentIntegrationTest` 在随机前缀隔离表上验证 V21、并发全站队列、删除项目后预算保留、超额事务回滚、告警去重和存储归属隔离。CI 配置 MySQL 8.4 服务执行连库测试；提交前本地使用 MySQL 8.0.46 实测，f32c4aa 的 GitHub 前后端 Linux CI 已于 2026-10-30 通过。

每日次数和秒数分别检查，任一上限触达就拒绝新请求；原有单账号同时最多 2 个任务仍保留，并与全站 3 个上限一起生效。按当前最长 60 秒视频计算，20 次通常先于 6000 秒触达，仍严格保留用户指定的两个数值。持续观察实际请求量、渲染时间及 R2 账单后再调整配置，不擅自修改价格或删除用户数据。
