## 1. 服务配置

| 服务 | Root Directory | Config as Code | 构建 / 启动 | 公网域名 |
|---|---|---|---|---|
| web | `/frontend` | `/frontend/railway.json` | Railpack：`npm run build` → `npm run start`（读 `PORT`，监听 0.0.0.0），健康检查 `/health` | 需要 |
| api | `/`（Dockerfile 需要整个 `backend/`） | `/backend/api/railway.json` | `backend/api/Dockerfile`（多阶段，JRE 21，非 root 用户，`SPRING_PROFILES_ACTIVE=prod`），健康检查 `/actuator/health`，`drainingSeconds` 30 | **不要**生成 |
| worker | `/` | `/backend/video-worker/railway.json` | `backend/video-worker/Dockerfile`（含 ffmpeg、fonts-noto-cjk），无健康检查，`restartPolicyType=ALWAYS`，`drainingSeconds` 35 | 不需要 |
| MySQL | Railway 模板，镜像改为 `mysql:8.4` | — | — | 不开放 TCP Proxy（管理时临时开） |

所有服务与 MySQL 在同一 Region（建议 Singapore）。根目录 `.dockerignore` 只把构建需要的源码送进镜像。

### 数据库迁移
Flyway 在 API 启动时执行：迁移失败 → API 启动失败 → 健康检查不通过 → 本次部署失败，旧版本继续服务，效果等同 Pre-deploy 命令。Worker 不执行迁移。
需要单独迁移（空库初始化、升级预演、CI）时：`java -jar tabitrace-api.jar --server.port=0 --app.migrate-only=true`（失败时退出码非 0）。
首次部署会在空库建好全部表（**V1–V19**），并写入东京官方内容、成就、目的地、视频模板、曲库目录（含版权记录）；不写入任何演示用户或旅行。

### 应用数据库账号
不要让应用使用 root：
```sql
CREATE USER 'tabitrace_app'@'%' IDENTIFIED BY '<随机强密码>';
GRANT ALL PRIVILEGES ON railway.* TO 'tabitrace_app'@'%';   -- 库名以 MYSQLDATABASE 为准
```

## 2. 变量（只列名称，值来源）

| 服务 | 变量 | 值来源 |
|---|---|---|
| api | `PORT=8080`；`DB_URL=jdbc:mysql://${{MySQL.MYSQLHOST}}:${{MySQL.MYSQLPORT}}/${{MySQL.MYSQLDATABASE}}?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC&sslMode=PREFERRED&allowPublicKeyRetrieval=true`；`DB_USERNAME` / `DB_PASSWORD`；`JWT_SECRET`（`openssl rand -base64 48`）；`APP_PUBLIC_URL` 与 `CORS_ALLOWED_ORIGINS`（web 正式域名）；`TRUST_PROXY_HEADERS=true`；`R2_*`；`MAIL_PROVIDER`（Railway 非 Pro 套餐不允许出站 SMTP，用 `resend`）+ `RESEND_API_KEY` 或 `MAIL_*`；`MAIL_FROM_ADDRESS` / `MAIL_FROM_NAME`；`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET`（不填则升级入口显示「支付暂未开放」） | Railway 变量引用、各服务商控制台 |
| worker | `DB_*`、`R2_*`（可用 `${{api.XXX}}` 引用）、可选 `R2_MUSIC_BUCKET` | 同上 |
| web | `API_INTERNAL_URL=http://${{api.RAILWAY_PRIVATE_DOMAIN}}:${{api.PORT}}`、`APP_URL`（与 api 的 `APP_PUBLIC_URL` 相同）、`NEXT_PUBLIC_MAP_STYLE_URL` 或 `NEXT_PUBLIC_MAP_TILE_URL`、`NEXT_PUBLIC_MAP_ATTRIBUTION`、可选 `NEXT_PUBLIC_MAP_API_KEY`；**不要**设置 `NEXT_PUBLIC_API_BASE_URL` | 构建阶段就要有 |

缺任何必要变量或仍是开发默认值时，API / Worker 拒绝启动，日志只列变量名。

## 3. 部署步骤

1. Railway → New Project → 从 GitHub 仓库部署；Project Settings 选 Region。
2. 添加 MySQL（镜像 `mysql:8.4`），创建应用账号。
3. Cloudflare R2：创建存储桶并绑定自定义域名；创建 API Token；桶 CORS 允许 `https://<web 域名>` 的 `PUT`（`Content-Type` 头）和 `GET`。
4. 添加 api 服务（Root `/`，Config `/backend/api/railway.json`），填变量，不生成域名。
5. 添加 web 服务（Root `/frontend`，Config `/frontend/railway.json`），填 `API_INTERNAL_URL` 等，生成域名。
6. 回到 api，把 `APP_PUBLIC_URL`、`CORS_ALLOWED_ORIGINS` 改成 web 正式域名，重新部署。
7. 添加 worker 服务（Root `/`，Config `/backend/video-worker/railway.json`）。
8. 发布背景音乐（见 §4），否则试听不可用、用该曲目的视频会降级为无音乐。
9. 冒烟测试：`https://<web 域名>/health` → `{"status":"ok"}`；注册（收验证码）→ 创建旅行 → 快速打卡 + 照片 → 总结 → 设置 → 退出。
10. Stripe（可后开）：Webhook 地址 `https://<web 域名>/api/v1/payments/stripe/webhook`，事件 `checkout.session.completed`、`checkout.session.async_payment_succeeded`。
11. 自定义域名后，同步更新 api 的 `APP_PUBLIC_URL` / `CORS_ALLOWED_ORIGINS` 与 web 的 `APP_URL`（web 需重新构建）。

## 4. 背景音乐发布

曲库与版权核验记录在 `backend/scripts/music/catalog.json`（只有 `APPROVED` 的曲目会出现在选择器里）。音频不进 Git：
```bash
node backend/scripts/music/music-sync.mjs    # 下载 → sha256 校验 → 响度 / 结构分析 → 生成 45 秒试听，输出到 .tabitrace/music/publish/
rclone copy .tabitrace/music/publish/music/previews  r2:<R2_BUCKET>/music/previews          # 公开桶
rclone copy .tabitrace/music/publish/music/originals r2:<R2_MUSIC_BUCKET>/music/originals   # 私有桶（推荐）
```
只能用一个公开桶时，在 Cloudflare 加 WAF 规则拦截 `/music/originals/*`。曲目作者（Scott Buckley、Kevin MacLeod）要求署名并登记了 YouTube Content ID：成片片尾自动署名，完成页提供完整署名文本。

## 5. 地图底图

生产**不使用** OpenStreetMap 官方瓦片（使用政策不允许商业流量）。没有配置时构建日志警告，地图只显示纯色底 + 标点。上线前选定服务商（如 MapTiler、Stadia Maps、自托管 PMTiles；OpenFreeMap 有免 Key 的公共样式，使用前确认条款），并按其许可显示署名。这些变量在构建时写入前端，修改后要重新部署 web。

## 6. CI / CD（现状与目标）

| 项目 | 现状 |
|---|---|
| 工作流 | 只有 `backend/.github/workflows/backend.yml`（`mvn -B clean test`），但**位置不对，GitHub 只读仓库根目录的 `.github/workflows/`，所以从未运行** |

## 8. 备份与恢复

| 对象 | 方案 | 状态 |
|---|---|---|
| 数据库 | 开启 Railway 卷备份（按套餐）；另外定期 `mysqldump --single-transaction --routines --no-tablespaces … \| gzip` 存到 R2 独立备份桶（现有 `backend/scripts/mysql-backup.sh` 是旧的单机方案：写到本机 `/opt/tabitrace/backups/mysql`、保留 30 天，不上传 R2，需要改造后才能用于 Railway）；保留建议：每日 7 天、每周 4 周、每月 6 个月 | 未实施 |
| 恢复 | 新建 MySQL → `gunzip -c 备份 \| mysql …` → api 指向新库（Flyway 会校验版本）；需要定期演练 | 未演练 |
| 照片与成片 | 开启 R2 对象版本 / 生命周期保留，或定期 rclone 同步到第二个桶 | 未实施 |
| RPO / RTO | ❓ 未定义 | — |

## 9. 上线后人工确认

- 发件域名 SPF / DKIM 已验证，验证码邮件能进收件箱
- R2 自定义域名可访问、桶 CORS 生效（能上传照片）
- 能试听音乐；生成带音乐的视频有音轨和片尾署名；`/music/originals/*` 返回 403 / 404
- 地图右下角显示底图服务商要求的署名
- 页面源代码里的 canonical 与 `og:url` 是正式域名
