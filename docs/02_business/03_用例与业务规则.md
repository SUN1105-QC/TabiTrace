# 用例与业务规则

**这是业务规则的唯一事实来源。** 规则都在后端执行，前端只做提前提示。每条规则后面标了代码位置（包名均在 `backend/api/src/main/java/com/tabitrace/` 下），改规则时代码和本文档一起改。
错误码的 HTTP 状态见 [异常与错误码设计](../06_backend/03_异常与错误码设计.md)；具体数值的常量见 [枚举与常量定义](../04_data/03_枚举与常量定义.md)。

## 0. 角色

系统只有一种登录用户，**没有管理员角色**。权限来自三件事：
1. **归属**：用户只能访问自己的旅行和旅行内的一切数据；
2. **套餐**：旅行是 FREE 还是 PRO（`trips.plan_type`）；
3. **会员**：账号是否有有效会员（`memberships`），目前只影响「我的音乐」。

另有一种匿名访客：持有有效分享令牌时，可以只读查看那一段旅行的公开成果。

## 1. 归属与可写

| 规则 | 代码 |
|---|---|
| R1.1 访问不存在的旅行 → `TRIP_NOT_FOUND`；访问别人的旅行 → `TRIP_FORBIDDEN` | `TripService.requireOwned` |
| R1.2 打卡、照片、行程、视频、地点关联都通过所属旅行校验归属（照片、视频还单独校验 `user_id`） | 各 Service 的 `requireWritable / requireOwned` |
| R1.3 **已归档的旅行只读**：修改旅行、标记完成、打卡、照片、行程、地点、视频生成都返回 `TRIP_ARCHIVED`（409）。允许：查看、删除旅行、取消归档、创建 / 撤销分享链接 | `TripService.requireWritable` |
| R1.4 自定义地点只能在它所属的旅行里使用（判断依据：`trip_places` 里有关联），否则 `CUSTOM_PLACE_FORBIDDEN` | `ItineraryService`、`CheckinService` |
| R1.5 视频选用的照片必须属于同一段旅行，否则 `VIDEO_PHOTO_INVALID` | `VideoService.validate` |
| R1.6 照片的 storageKey 必须在该旅行自己的存储路径下，否则 `INVALID_STORAGE_KEY` | `PhotoService` |

## 2. 旅行

| 规则 | 代码 |
|---|---|
| R2.1 结束日期不能早于开始日期（`INVALID_TRIP_DATES`）；人数 1~100，默认 1 | `TripService.validateDates`、`TripDtos` |
| R2.2 **FREE 名额**：没有终身 Pro 的用户，同时只能有 1 个未归档的 FREE 旅行（`FREE_TRIP_LIMIT`）。归档的旅行不占名额；取消归档 FREE 旅行时同样检查名额 | `TripService.create / unarchive` |
| R2.3 有终身 Pro 的用户新建旅行直接是 PRO，不受名额限制 | `TripService.create` |
| R2.4 新旅行一律 `status=PLANNING`、`visibility=PRIVATE`（用户设置里的 `default_visibility` 目前不生效） | `TripService.create` |
| R2.5 勾选「加入官方探索」且目的地匹配到启用的官方城市（先按城市名，再按目的地名）时，把该城市全部官方地点加入旅行 | `TripService.create / officialCityOf` |
| R2.6 第一次打卡时，PLANNING 自动变为 ONGOING | `CheckinService.create` |
| R2.7 「标记完成」把旅行设为 COMPLETED；归档后取消归档统一恢复为 COMPLETED（不保留原状态） | `TripService.complete / unarchive` |
| R2.8 删除旅行会级联删除打卡、照片记录、行程、分享链接、视频项目、成就记录；支付记录保留（`trip_id` 置空）；存储里的照片文件同时删除（失败则整体回滚）。成片通过 V22 持久化清理任务由 Worker 删除，失败重试 | `TripDeletionService`、外键（V1、V17） |

## 3. 地点与行程

| 规则 | 代码 |
|---|---|
| R3.1 官方地点只能从官方城市加入（`OFFICIAL_PLACE_NOT_FOUND`）；同一地点在一段旅行里只出现一次（`uk_trip_place`） | `OfficialCityService.addToTrip`、V1 |
| R3.2 自定义地点只能创建、从旅行移除，**不能修改**；移除只删关联，`places` 记录会残留（技术债） | `PlaceService` |
| R3.3 行程日期必须在旅行日期范围内（`ITINERARY_DATE_OUTSIDE_TRIP`）；必须选地点或填地点名（`ITINERARY_PLACE_REQUIRED`） | `ItineraryService` |
| R3.4 行程状态只能是 PLANNED / DONE / CANCELLED，默认 PLANNED | `ItineraryService.normalizeStatus` |
| R3.5 行程转打卡：已经 DONE 且已有打卡的行程不能再打卡（`ITINERARY_ALREADY_CHECKED_IN`）；指定地点与行程地点不一致时拒绝（`ITINERARY_PLACE_MISMATCH`） | `CheckinService.fromItinerary / create` |

## 4. 打卡

| 规则 | 代码 |
|---|---|
| R4.1 FREE 旅行最多 10 个打卡（`FREE_CHECKIN_LIMIT`）；PRO 不限 | `CheckinService.checkFreeLimit` |
| R4.2 打卡的**当地日期**（按打卡时区，没有则按用户时区）必须在旅行日期范围内（`CHECKIN_TIME_OUTSIDE_TRIP`） | `CheckinService.validateLocalDate` |
| R4.3 坐标范围：纬度 -90~90，经度 -180~180 | `@Latitude / @Longitude` |
| R4.4 打卡保存地点名称和区域的快照（`place_name_snapshot`、`area_snapshot`），地点以后改名也不影响历史记录 | `CheckinService` |
| R4.5 关联行程的打卡：创建时行程变 DONE，删除时恢复 PLANNED | `CheckinService.create / delete` |
| R4.6 快速打卡：打卡与照片元数据在一个事务里保存；没有地点名时记为「随手记录」；定位精度 ≤50 米且 60 米内有旅行里的地点时自动匹配该地点；天气、定位失败不影响保存，也不回填猜测值 | `QuickCheckinService`、`GeoService` |
| R4.7 天气只取打卡时刻前后的数据（当前 ±90 分钟；历史最多回查 92 天） | `WeatherService` |

## 5. 照片

| 规则 | 代码 |
|---|---|
| R5.1 FREE 旅行最多 10 张照片（申请上传和登记时都检查，`FREE_PHOTO_LIMIT`） | `PhotoService.presign / register` |
| R5.2 单张 ≤20MB；缩略图 ≤1MB、中图 ≤5MB；类型 JPG / PNG / WebP / GIF / HEIC | `PhotoService` |
| R5.3 登记前确认对象确实已上传（local 查文件，R2 调 HeadObject），否则 `PHOTO_UPLOAD_MISSING` | `PhotoService.register` |
| R5.4 设为封面的照片必须属于该旅行；批量操作只支持 FEATURE / UNFEATURE / DELETE | `PhotoService.setCover / batch` |
| R5.5 删除照片同时删除存储对象（原图和两档尺寸） | `PhotoService.delete` |

## 6. 旅行总结

| 规则 | 代码 |
|---|---|
| R6.4 统计不存计数，每次按打卡和照片实时计算；地点数按「地点 id，没有则按地点名」去重 | `SummaryService.get` |
| R6.5 官方探索度 = 已打卡的官方地点数 ÷ 东京官方地点总数（非东京旅行为 0） | `SummaryService.get`、`TripService.isTokyo` |
| R6.6 成果准备度：有打卡即可分享（`shareReady`）；至少 3 张照片且有打卡才能做视频（`videoReady`） | `SummaryService.get` |

## 7. 分享

| 规则 | 代码 |
|---|---|
| R7.1 创建分享链接：令牌为 24 字节随机数；有效期默认取用户设置（0 = 长期、7、30 天）；旅行 visibility 变为 UNLISTED | `ShareService.create` |
| R7.2 撤销链接后，如果这段旅行已经没有有效链接，visibility 恢复 PRIVATE | `ShareService.revoke` |
| R7.3 公开页只返回：旅行信息、总结、时间轴、精选照片、昵称；**不返回邮箱和设置** | `ShareService.publicView` |
| R7.4 坐标默认保留两位小数（约 1 公里），用户在隐私设置开启「分享精确位置」后才返回原值 | `ShareService.coarsen` |
| R7.5 链接无效、过期或已撤销 → `SHARE_LINK_INVALID`（404）；每次访问浏览次数 +1 | `ShareService.publicView` |
| R7.6 分享图导出规格：FREE 标准清晰度、海报宽 1080、带水印；PRO 高清、海报宽 1440、2 倍图、无水印 | `PlanService.SHARE_FREE / SHARE_PRO`（前端按此导出） |

## 8. Travel Story 视频

| 规则 | 代码 |
|---|---|
| R8.1 模板：FREE 旅行只能用 FREE 模板（旅行日记 JOURNAL），否则 `PRO_TEMPLATE_REQUIRED`（403） | `VideoService.validate` |
| R8.2 照片：至少 1 张、不能重复；FREE 最多 10 张（`PRO_PHOTO_LIMIT`，403），PRO 最多 30 张（`VIDEO_PHOTO_LIMIT`） | 同上 |
| R8.3 时长 15 / 30 / 60 秒，60 秒需要 PRO（`PRO_DURATION_REQUIRED`）；清晰度 720p / 1080p，1080p 需要 PRO（`PRO_QUALITY_REQUIRED`）；比例 9:16 / 4:5 / 16:9 | 同上 |
| R8.4 音乐：FREE 只能用 FREE 曲目（`PRO_MUSIC_REQUIRED`）；可以选「无音乐」；「我的音乐」需要有效会员，且音乐状态必须是 READY | 同上、`MembershipService.require` |
| R8.5 封面必须是已选照片之一 | 同上 |
| R8.6 只有 DRAFT 能直接修改（`VIDEO_NOT_EDITABLE`）；已生成的视频要「重新编辑」复制出新的 DRAFT | `VideoService.update / duplicate` |
| R8.7 开始生成时**全部条件重新校验**（照片可能被删、套餐或目录可能变了、会员可能到期），然后冻结分镜 | `VideoService.render` |
| R8.8 分镜里至少要有一个照片段落（`VIDEO_STORY_EMPTY`） | 同上 |
| R8.9 同一用户同时最多 2 个视频处于 QUEUED / PROCESSING（`VIDEO_QUEUE_LIMIT`，429）；正在排队或生成的视频不能再次提交 | 同上 |
| R8.10 正在生成（PROCESSING）的视频不能删除 | `VideoService.delete` |
| R8.11 FREE 成片 720p 带水印；成片片尾自动写入音乐署名 | Worker `ScenePainter`、`FfmpegRenderer` |
| R8.12 音乐文件不可用时成片不失败，自动改为无音乐版本并提示用户 | Worker（`MUSIC_FALLBACK`） |
| R8.13 旅行路线动画已下线（V16），模板和权益里都不能再出现 | ADR-011 |

## 9. 我的音乐与会员

| 规则 | 代码 |
|---|---|
| R9.1 上传、保存、试听自己的音乐需要有效会员；非会员 403 `CUSTOM_MUSIC_REQUIRES_MEMBERSHIP`（details 说明是从未开通还是已到期） | `MembershipService.require` |
| R9.2 **Trip Pro 不等于会员**：只升级某段旅行不能上传音乐；目前开通会员的唯一方式是买断终身 Pro | `PaymentService.paid`、`MembershipService` |
| R9.3 会员是否有效：状态 ACTIVE 且（`expires_at` 为空或晚于现在）；不需要定时任务改状态 | `MembershipService` |
| R9.4 限制：单个文件 ≤30MB、最多 20 首、总计 ≤500MB、时长 3 秒～30 分钟；只支持 MP3 / M4A / WAV，扩展名必须与真实格式一致 | `app.user-music.*`、`UserMusicService` |
| R9.5 上传前必须勾选版权确认（`COPYRIGHT_CONFIRMATION_REQUIRED`），确认时间会记录 | `UserMusicService` |
| R9.6 会员到期后音乐变为只读，至少保留 365 天，目前不自动删除；到期后不能用于新视频 | `app.user-music.retention-days-after-expiry`、R8.7 |

## 10. 支付

| 规则 | 代码 |
|---|---|
| R10.1 Trip Pro：已经是 PRO 的旅行不能再买（`TRIP_ALREADY_PRO`）；终身 Pro：已拥有不能再买（`LIFETIME_ALREADY_OWNED`） | `PaymentService` |
| R10.2 未配置真实支付时不能付款（`PAYMENTS_UNAVAILABLE`）；金额低于支付渠道最低收款额时不能付款（`PAYMENT_CHANNEL_UNAVAILABLE`，503）；升级页据方案配置显示「支付暂未开放」 | `PaymentService.requireChargeable`、`PlanService` |
| R10.3 只有 Webhook 里 `payment_status=paid` 才算付款成功；Webhook 必须通过签名校验 | `PaymentService.webhook` |
| R10.4 Trip Pro 一次性付款，旅行永久 PRO，不续费不过期；终身 Pro 付款后账号下现有和以后的旅行都是 PRO，并写入永久会员记录 | `PaymentService.paid` |
| R10.5 开发环境（mock）下单即视为付款成功 | `PaymentService` |

## 11. 账号

| 规则 | 代码 |
|---|---|
| R11.1 注册必须先通过邮箱验证；令牌一次性、30 分钟有效、与邮箱绑定 | `AuthService.register`、`EmailVerificationService` |
| R11.2 密码 8~100 位；新密码不能与当前密码相同 | `AuthDtos`、`UserService` |
| R11.3 修改密码、重置密码后撤销其他设备的登录 | `UserService`、`AuthService` |
| R11.4 「退出其他设备」不能用来退出当前设备（`SESSION_IS_CURRENT`） | `AuthService.revokeSession` |
| R11.5 昵称 ≤30 字、简介 ≤120 字；语言 zh-CN / ja-JP / en-US；距离单位 KM / MI | `UserService` |
| R11.6 头像 JPG / PNG / WebP、≤5MB | `UserService` |
| R11.7 注销：需要密码；进入 7 天冷静期并退出所有设备；冷静期内登录并确认可撤销；到期删除账号与存储文件 | `AccountDeletionService`、`AuthService.login` |
