# 收费与退款运营决策草案

供运营确认，不对外发布，不构成用户已接受的服务条款。技术实现不能代替退款资格、时限、税务与服务主体决策。

## 当前已经确定的程序行为

- 单次 Trip Pro：CNY 400 分，一段旅行一次性升级，不自动续费。
- 终身 Pro：CNY 100000 分，账号现有及未来旅行为 PRO，并获得账号会员权益。
- 未通过渠道确认的订单不发放权益；回跳成功参数不代表付款成功。
- 项目没有开放用户退款发起 API；经确认的退款由运营在 Stripe 后台处理，项目通过回调/对账同步结果。
- 新付款的全额退款回收该笔付款带来的权益；部分退款保留；争议期间暂停、胜诉恢复。其他独立付款和赠送权益保留。
- 退款不会自动删除旅行、照片、视频或音乐。来源不明的 V20 以前旧 PRO 旅行保守保留，历史退款需人工核对。

## 可执行的人工处理流程

1. 根据已登录用户的订单编号核对付款记录与渠道 Session / PaymentIntent，避免只凭截图或回跳地址判定已支付。
2. 按已经批准的对外规则确定退款资格和金额；未确定规则时不由程序擅自承诺无条件退款或拒绝退款。
3. 在正确的 Stripe 账户及环境中核对交易后执行退款，记录渠道退款编号；部分与全额退款不能混用。
4. 等待回调同步，或使用订单「查询结果」进行核实。渠道处理中、失败与成功需分别说明，不能把点击退款当成已到账。
5. 核对权益结果，尤其是同时存在单次/终身付款、历史赠送或争议的账号；不手动删除订单来释放状态。
6. 按确认的客服渠道回复处理结果，并保留必要财务凭证。

真实 Stripe Sandbox、退款和争议测试必须使用测试环境。当前会话没有提供测试 Secret Key / Webhook Secret，因此只完成离线签名、HTTP 协议、状态机及 MySQL 验证；真实支付验收仍待测试环境配置后执行。
