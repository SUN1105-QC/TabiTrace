# 状态与生命周期设计

数据库里所有状态列都是 `VARCHAR` + 默认值，**没有数据库层的 ENUM 或 CHECK 约束**，合法取值由代码保证。取值清单见 [枚举与常量定义](../04_data/03_枚举与常量定义.md)。

## 1. 旅行 `trips.status`

```
            第一次打卡（自动）        标记完成（用户）
PLANNING ─────────────────────▶ ONGOING ─────────────────▶ COMPLETED
    │                              │                           ▲
    │            标记完成（用户）    │                           │ 取消归档（统一恢复为 COMPLETED）
    └──────────────────────────────┴──────────▶ ARCHIVED ──────┘
                         归档（用户，任意状态都可以）
```

| 转换 | 谁 | 副作用 |
|---|---|---|
| 创建 → PLANNING | 用户 | 可能加入官方地点；plan_type 为 FREE 或 PRO（终身 Pro 用户） |
| PLANNING → ONGOING | 系统（第一次打卡） | — |
| 任意（非 ARCHIVED）→ COMPLETED | 用户 | 触发成就计算（「旅程完成」） |
| 任意 → ARCHIVED | 用户 | 旅行变为只读；不再占 FREE 名额 |
| ARCHIVED → COMPLETED | 用户 | FREE 旅行需要有空余名额 |
| 删除 | 用户 | 级联删除旅行内数据，支付记录保留 |

`trips.plan_type`：FREE → PRO（Trip Pro 付款或终身 Pro），**只升不降**。
`trips.visibility`：PRIVATE ⇄ UNLISTED（创建分享链接 → UNLISTED；最后一个有效链接被撤销 → PRIVATE）。

## 2. 行程 `itinerary_items.status`

```
PLANNED ──（关联的打卡创建）──▶ DONE ──（关联的打卡删除）──▶ PLANNED
   └──（用户修改）──▶ CANCELLED（用户可以改回）
```

## 3. 视频项目 `video_projects.status`

```
DRAFT ──开始生成──▶ QUEUED ──Worker 领取──▶ PROCESSING ──▶ COMPLETED
                      ▲                         │  └────────▶ FAILED
                      │                         │
                      └──── Worker 收到停机信号且宽限期内没做完，放回队列
COMPLETED / FAILED ──重新生成──▶ QUEUED
COMPLETED / FAILED ──「重新编辑」──▶ 复制出新的 DRAFT（原项目不变）
```

| 状态 | 允许的操作 |
|---|---|
| DRAFT | 修改、预览分镜、生成、删除 |
| QUEUED | 删除（还没开始渲染）；不能修改、不能再次提交 |
| PROCESSING | 只能等待；不能删除 |
| COMPLETED | 播放、下载、重新生成、复制、删除 |
| FAILED | 重试（重新生成）、复制、删除 |

- `render_stage`（PROCESSING 期间的进度说明）：Worker 领取时为 `PREPARING`，渲染中按阶段更新，上传时为 `UPLOADING`，结束后清空。
- 失败原因写在 `error_code` / `error_message`（Worker 码如 `PHOTO_DOWNLOAD_FAILED`、`ENCODE_FAILED`、`STORAGE_FAILED`；看门狗写 `RENDER_INTERRUPTED`）。
- 看门狗：PROCESSING 超过 300 秒没有心跳 → FAILED / `RENDER_INTERRUPTED`。
- 开发环境的 Mock 渲染器：直接把 QUEUED 标为 COMPLETED，`renderer=MOCK`，地址是不能播放的 `example.invalid` 占位。

## 4. 支付 `payments.status`

```
PENDING（创建 Checkout）──Webhook payment_status=paid──▶ PAID
```
- mock 模式下创建即 PAID。
- **没有失败、过期、退款状态的处理**：用户放弃付款时记录停留在 PENDING（❓ 是否需要清理或标记待确认）。

## 5. 用户 `users.status`

```
ACTIVE ──申请注销（输入密码）──▶ DELETION_PENDING ──7 天后定时任务──▶ （账号被删除）
   ▲                                   │
   └──── 冷静期内登录并确认撤销 ─────────┘
```
登录时 status 不是 ACTIVE（也不是冷静期）就返回 `USER_DISABLED`；但代码里**没有任何把用户设为其他状态（如禁用）的入口** ❓ 是否需要管理端待确认。

## 6. 会员 `memberships`

- `status`：ACTIVE / CANCELLED / REVOKED（目前代码只写入 ACTIVE）。
- 是否有效：`status=ACTIVE` 且 `expires_at` 为空或晚于现在；到期不改状态，读取时计算出 EXPIRED 视图。
- `source`：LIFETIME（买断）/ SUBSCRIPTION（预留）/ GRANT（人工赠送，预留）。

## 7. 我的音乐 `user_music.status`

```
UPLOADING（申请上传地址）──完成上传并通过检查──▶ PROCESSING ──▶ READY
      │                                           └──────▶ FAILED（failure_code 说明原因）
      └──超过 120 分钟未完成──▶ 清理任务删除
READY / FAILED ──用户删除──▶ DELETED（软删除，存储文件由清理任务删除后记 purged_at）
```

## 8. 其他

| 对象 | 生命周期 |
|---|---|
| 分享链接 `share_links.status` | ACTIVE → REVOKED（用户撤销）；过期由 `expires_at` 判断，不改状态 |
| 登录会话 `refresh_tokens` | 签发 → 每次刷新轮换（旧的撤销）→ 退出 / 改密码 / 注销时撤销；过期或撤销 7 天后由清理任务删除 |
| 邮箱验证 `email_verifications` | 发送（`send_status`：PENDING → SENT / FAILED / THROTTLED）→ 校验成功得到令牌 → 令牌使用一次即失效；记录保留 7 天后清理 |
| 登录失败 `login_failures` | 登录成功或重置密码后清除该邮箱记录；过期记录定时清理 |
| 官方城市 `official_cities.status` | 默认 DRAFT，只有 `ACTIVE` 的城市会匹配「加入官方探索」（目前只有 TOKYO） |
| 曲库 `video_music.status` | REVIEW_REQUIRED / APPROVED；只有 APPROVED 且 `enabled` 的曲目可以选择 |
