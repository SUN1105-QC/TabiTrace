# 认证设计（你是谁）

## 1. 方式

邮箱 + 密码（BCrypt）。没有第三方登录（OAuth）。注册前必须验证邮箱。

## 2. 令牌与会话

| 凭证 | 有效期 | 保存位置 | 说明 |
|---|---|---|---|
| 访问令牌（JWT，HS 签名，`JWT_SECRET`） | 15 分钟 | **只在浏览器内存** | 带 `sid`（会话）；`JwtAuthenticationFilter` 每次请求检查该会话仍有效，所以退出后旧访问令牌立即失效 |
| refresh token（JWT） | 30 天 | **HttpOnly Cookie `tt_refresh`**（SameSite=Strict、path `/api/v1`、生产 Secure） | 数据库 `refresh_tokens` 存一行；**每次刷新都轮换**（旧的撤销、签发新的），同一设备的多次轮换用 `session_id` 串起来 |
| 会话标记 | — | localStorage `tabitrace-session` | 只表示「这台设备登录过」，不含凭证；页面据此决定先静默刷新还是直接跳登录 |

旧版本把令牌存在 localStorage，现在读到旧值会删除访问令牌、把旧 refresh token 一次性迁移进 Cookie。

## 3. 流程

| 流程 | 说明 |
|---|---|
| 注册 | 验证码 → 一次性邮箱验证令牌（30 分钟）→ 注册，令牌在注册事务里加行锁消费，并发提交只有一次成功；邮箱唯一以数据库约束为准 |
| 登录 | 邮箱不存在时也执行一次 BCrypt（防止按响应时间判断账号是否存在）；错误统一 `INVALID_CREDENTIALS`；成功后清除该邮箱的失败记录 |
| 刷新 | `POST /auth/refresh` 只读 Cookie；多标签页同时刷新时，后到的会失败一次，前端等待后重试（最多 2 次） |
| 退出 | 只退出当前设备并清 Cookie；访问令牌失效时也能用 Cookie 撤销会话（幂等） |
| 改密码 | 撤销其他设备 |
| 找回密码 | 验证码 → 令牌 → 新密码；撤销所有会话，当前设备直接登录 |
| 设备管理 | 列出活跃会话（设备名由 User-Agent 解析）；可退出单台或其他所有设备 |
| 注销 | 进入冷静期即撤销所有会话 |

## 4. 防护

| 风险 | 措施 |
|---|---|
| 暴力猜密码 | 15 分钟内同邮箱失败 8 次或同 IP 失败 40 次 → 429（`login_failures` 表，IP 只存 HMAC 哈希） |
| 验证码滥发 | 同邮箱 60 秒冷却、每小时 5 次；同 IP 每小时 20 次；验证码 10 分钟、最多错 5 次 |
| 账号探测 | 注册与找回密码的发送接口对「已注册 / 未注册 / 不可用」返回完全相同的响应，只有邮件内容不同 |
| CSRF（refresh / logout 依赖 Cookie） | Cookie `SameSite=Strict`；另外检查 `Sec-Fetch-Site`：same-origin / none 放行，cross-site 拒绝（`CROSS_SITE_REQUEST`），same-site 或旧浏览器再按 `Origin` 白名单判断 |
| XSS 读取凭证 | 访问令牌不落盘，refresh 是 HttpOnly |
| 验证码 / 令牌泄露 | 只存哈希（验证码 HMAC-SHA256，令牌 SHA-256）；不出现在响应和日志里 |
| 弱密钥上线 | prod profile 启动时校验 `JWT_SECRET`：缺失、短于 32 字节或含 `change-me` 拒绝启动 |

## 5. 前端行为

见 [前端架构设计](../05_frontend/01_前端架构设计.md) §4：请求前无令牌但有会话标记先刷新；401 刷新一次并重放；失败清会话跳 `/login?next=…`；其他标签页退出时，本页内存里的令牌同步作废。
