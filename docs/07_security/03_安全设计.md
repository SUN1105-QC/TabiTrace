# 安全设计（含日志与审计）

认证细节见 [认证设计](01_认证设计.md)，访问控制见 [权限设计](02_权限设计.md)。

## 1. 检查清单

| 主题 | 现状 | 位置 |
|---|---|---|
| XSS | React 默认转义；凭证不在 localStorage；`X-Content-Type-Options: nosniff` | `frontend/next.config.ts` |
| 点击劫持 | `X-Frame-Options: DENY`、`frame-ancestors 'none'` | 同上 |
| 其他响应头 | `Referrer-Policy: strict-origin-when-cross-origin`；`Permissions-Policy` 只给本站定位与相机，禁用麦克风；不输出 `X-Powered-By` | 同上 |
| CSRF | API 用 Bearer 令牌，Spring CSRF 关闭；依赖 Cookie 的 refresh / logout 用 SameSite=Strict + Fetch Metadata / Origin 检查 | `RefreshCookies.crossSite` |
| CORS | 白名单（`CORS_ALLOWED_ORIGINS`）；prod 拒绝 `*` 和 localhost；生产走同源代理基本不需要 CORS。⚠ 允许的方法里没有 PATCH（技术债） | `SecurityConfig` |
| SQL 注入 | MyBatis `#{}` 参数绑定；没有字符串拼接 SQL（❓ 未逐条审计动态 SQL） | 各 Mapper |
| 输入校验 | Jakarta Validation（长度、邮箱、坐标范围）+ Service 层规则；数据库约束错误不向前端暴露细节 | DTO、`GlobalExceptionHandler` |
| 文件上传 | 预签名签入大小和类型；登记前确认对象存在；storageKey 限定在本人目录、禁止 `..`；本地上传要 HMAC 签名；音乐校验扩展名与真实格式一致。⚠ 照片只校验声明的 MIME，不检查文件内容（技术债） | `PhotoService`、`LocalStorageService`、`UserMusicService` |
| 私有文件 | 我的音乐、音乐原曲不能无签名读取；生产需额外配置桶权限（P1） | `LocalStorageController` |
| 限流 | 登录、验证码（数据库计数）；视频同时生成数 2。⚠ 其他接口（如照片预签名、逆地理）没有限流 ❓ | — |
| 客户端 IP | 只在 `TRUST_PROXY_HEADERS=true`（API 不对公网）时信任 `X-Forwarded-For` 最右侧；否则只信本机 nginx 的 `X-Real-IP` | `ClientIp` |
| 密钥 | 只来自环境变量；prod 缺失或使用开发默认值拒绝启动（只报变量名）；仓库里的 `*-change-me-*`、`tabitrace_dev` 仅限本地 | `ProductionSecretsValidator`、Worker `WorkerProductionValidator` |
| 敏感数据 | 密码 BCrypt；验证码 / 令牌 / IP 只存哈希；分享页不返回邮箱、坐标默认粗化 | — |
| 支付 | 以 Stripe Webhook 为准；签名校验；`provider_payment_id` 唯一防重复 | `PaymentService` |
| 依赖安全 | 09-18 审计时 `npm audit` 0 漏洞；之后 ❓ 未复查；后端没有依赖扫描 | — |
| 健康检查 | 生产 `show-details: when_authorized`，只暴露 health / info | `application*.yml` |

## 2. 日志

| 类别 | 现状 |
|---|---|
| 系统日志 | Spring 默认 Logback 输出到控制台；local profile 下 `com.tabitrace` 为 DEBUG；未配置日志文件、轮转或集中收集 |
| 业务日志 | 只有少量关键事件：迁移完成、申请注销 / 删除账号、会话清理数量、视频看门狗、外部服务失败（邮件、Stripe、存储、逆地理、天气） |
| 安全日志 | 登录失败不写日志，只记入 `login_failures` 表（IP 哈希）；未处理异常写 ERROR |
| 日志中的个人信息 | ⚠ 邮件发送失败日志里包含收件邮箱（`to=`）；其余不记录令牌、验证码、密码 |

## 3. 审计

**没有审计日志**：不记录「谁在什么时间对什么资源做了什么」。现有可追溯的数据只有：支付记录、登录会话（设备、时间）、注销申请时间、我的音乐版权确认时间、曲库授权核验记录。上线前是否需要审计日志 ❓ 待确认。
