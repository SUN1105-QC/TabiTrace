# 文件存储设计

照片、头像、自定义音乐、成片、曲库音频都**不进数据库**，数据库只存 `storage_key` 和访问地址。

## 1. 存储实现

接口 `backend/api/.../photo/storage/StorageService`，由 `app.storage.mode`（环境变量 `STORAGE_MODE`）选择：

| 模式 | 实现 | 用途 |
|---|---|---|
| `local` | `LocalStorageService` | 开发：写到 `LOCAL_STORAGE_DIR`（默认 `./.tabitrace/uploads`，即 `backend/api/.tabitrace/uploads`）；上传与读取经过 API 的 `/api/v1/local-storage/*` |
| `r2` | `R2StorageService` | 生产：Cloudflare R2（S3 兼容）；浏览器直接对 R2 预签名 PUT；公开访问用 `R2_PUBLIC_BASE_URL` |
| `mock` | `MockStorageService` | 没有配置 `app.storage.mode` 时的兜底（只返回 `mock://` 地址，不存文件）；正常配置下用不到 |

prod profile 固定为 `r2`。

## 2. 路径布局

| 内容 | key | 公开性 |
|---|---|---|
| 照片原图 | `users/{userId}/trips/{tripId}/{uuid}.{ext}` | 公开地址 |
| 照片缩略图 / 中图 | 同目录，文件名带 `-thumb.` / `-medium.` | 公开地址 |
| 头像（原图、小图） | `users/{userId}/avatar/{uuid}.jpg` | 公开地址 |
| 成片（R2） | `users/{userId}/trips/{tripId}/videos/{projectId}.mp4` | 公开地址 |
| 成片（本地开发） | `frontend/public/generated-videos/project-{id}/output.mp4`（由 next dev 直接提供） | 公开 |
| 我的音乐 | `user-music/{userId}/…` | **私有**：只能用短时签名地址试听（默认 900 秒） |
| 曲库试听 | `music/previews/…` | 公开（R2 公开桶） |
| 曲库原曲 | `music/originals/…` | **私有**：只给 Worker 读取（建议放没有公开域名的私有桶，Worker 用 `R2_MUSIC_BUCKET`） |

## 3. 上传流程

```
1. POST 预签名接口（照片 / 头像 / 我的音乐），服务端检查：归属、额度、声明的大小和类型
2. 浏览器 PUT 文件到返回的 uploadUrl
     - R2：S3 预签名，有效期 15 分钟，签入 Content-Type 和 Content-Length（大小不一致会被拒绝）
     - local：`/local-storage/upload?key&expires&signature`，HMAC 签名、15 分钟有效，未签名返回 403，超过大小返回 413
3. POST 登记 / 完成接口，服务端确认对象确实存在（local 查文件、R2 调 HeadObject）后写数据库
```
- 照片的两档尺寸由浏览器生成，用 `variantOf` + `variant` 单独申请地址；尺寸版本失败不影响原图。
- 服务端校验 storageKey 必须在该用户该旅行的目录下，并且不能包含 `..`。

## 4. 限制

| 内容 | 大小 | 类型 |
|---|---|---|
| 照片原图 | ≤20MB | JPG、PNG、WebP、GIF、HEIC |
| 缩略图 / 中图 | ≤1MB / ≤5MB | JPEG |
| 头像 | ≤5MB | JPG、PNG、WebP |
| 我的音乐 | ≤30MB，每人 20 首、共 500MB，时长 3 秒～30 分钟 | MP3、M4A、WAV（扩展名与实际格式必须一致） |

## 5. 读取

- 照片、头像、成片、试听：直接用公开地址（local 模式下 `/local-storage/file?key=…`，`Cache-Control: no-cache`）。
- 我的音乐：`GET /user/music/{id}/play-url` 返回短时签名地址；local 模式下 `/local-storage/file` 校验签名，支持 Range（拖动进度条）。
- 曲库原曲：HTTP 一律 404，只给 Worker 从目录或私有桶读取。
- 生产里官方景点图不在对象存储，在前端 `public/images/explore/hd/`，由 Next 提供并缓存 30 天。

## 6. 清理

| 时机 | 清理内容 | 代码 |
|---|---|---|
| 删除照片 | 原图与两档尺寸；同时清除引用它的旅行封面、视频封面 | `PhotoService.remove` |
| 删除旅行 | 照片原图与两档尺寸同步删除；所有视频成片登记持久化清理任务，事务回滚时任务也回滚 | `TripDeletionService` |
| 删除视频项目 | 同事务登记成片清理任务；Worker 删除该项目 R2 标准对象与本地 `project-{id}` 目录 | `VideoService.delete`、Worker `VideoOutputLifecycle` |
| 更换 / 删除头像 | 旧头像文件 | `UserService` |
| 注销到期 | `users/{id}/` 与 `user-music/{id}/` 整个目录；同事务登记全部视频清理任务以补清本地成片 | `AccountDeletionService.purge` |
| 我的音乐 | 超过 120 分钟未完成的上传；已删除或失败的音乐，在使用它的视频生成结束后删除存储文件 | `UserMusicCleaner`（每 10 分钟） |
| 视频中间文件 | 成功只保留成片；失败清空工作目录；Worker 启动时清扫上次遗留的中间文件 | Worker |

2026-10-29 本地补齐成片清理，依赖 V22，尚未部署：Worker 默认每 60 秒扫描至多 20 个到期任务，可通过 `VIDEO_OUTPUT_CLEANUP_INTERVAL_MS` 配置间隔；失败保留任务并延后 5 分钟。Worker 停止或正在执行长任务时，清理会延后，不能承诺删除 API 返回即完成公开对象清理。对象删除也不会撤回已下载副本或主动刷新 CDN 缓存。

发布成片与删除使用同一项目行锁：若发布先获得锁，删除等发布提交后登记任务；若删除先提交，Worker 不再上传。单独删除 PROCESSING 项目仍返回 409；删除整个旅行/账号可级联移除进行中的项目，Worker 随后跳过发布并清理本地结果。清理任务不接受用户路径，只按服务器保存的账号/旅行/项目编号推导标准 R2 key 与工作目录。

本方案只保证新版本删除路径产生的任务。历史上已删除数据库记录而残留的成片无法从这些记录还原，需要后续存储清单对账，不能盲目批量删除。手工 SQL 删除也不会经过应用登记清理任务。

发布时先由 API 执行 V22，再启动新版 Worker。运维可只读检查待处理数量、重试数量与最早任务时间，持续积压时检查 Worker 是否运行、桶权限和磁盘访问；不要通过删除任务记录来消除告警：

```sql
SELECT COUNT(*) AS pending, COALESCE(SUM(attempts > 0), 0) AS retrying,
       MIN(created_at) AS oldest_pending
FROM video_output_deletions;
```

## 7. 生产注意（未完成，见 P1）

- 照片和「我的音乐」目前在同一个公开桶，建议在 R2 / Cloudflare 禁止公开访问 `user-music/*`，或为用户音乐单独配置私有桶。
- 音乐原曲如果只能放在公开桶，需要 WAF 规则拦截 `/music/originals/*`。
- R2 桶 CORS 需要允许 web 域名的 `PUT`（`Content-Type` 头）与 `GET`。
