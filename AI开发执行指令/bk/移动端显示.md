==================================================
三、响应式原则
==================================================

Desktop：

>= 1024px

尽量保持现有页面布局和视觉。

Tablet：

768px ~ 1023px

可以合理从多栏转双栏 / 单栏。

Mobile：

< 768px

必须真正重新组织布局。

不要：

把 Desktop 页面按比例缩小。

不要通过：

font-size 全部调小

解决布局问题。

Mobile 应重新考虑：

内容顺序
信息密度
操作优先级
导航
卡片数量
Sticky / Fixed 控件

==================================================

先运行项目。

逐 Route 检查。

记录并修复以下问题：

A. 页面横向溢出

检查是否出现：

100vw + padding

fixed width container

确保 Mobile：

--------------------------------------------------

B. Desktop Sidebar

Mobile 下：

Desktop Sidebar 不应该继续占据页面宽度。

复用。

使用统一 Mobile Navigation。

--------------------------------------------------

检查每个页面 Mobile Header 是否统一。

检查所有：

==================================================
最终目标
==================================================

这次任务不是：

“让所有页面在手机上不报错”。

而是：

让整个 TabiTrace 在 Mobile 上真正像一个经过专门设计的产品。

Desktop 和 Mobile 可以拥有不同的信息布局，

但应该拥有：

同一套品牌语言
同一套业务逻辑
统一的 Navigation
统一的 Spacing
统一的交互方式

用户从：

首页
登录
创建旅行
打卡
看照片
Travel Story
旅行回忆
成就
设置

一路使用下来，

不应该感觉每个页面都是独立开发出来的。

现在请：

1. 分析项目
2. 列出所有主要 Route
3. 运行项目
4. 逐个进行 Mobile Audit
5. 直接修复
6. 执行第二轮 Regression
7. 最后输出完整报告

不要停留在建议阶段。
